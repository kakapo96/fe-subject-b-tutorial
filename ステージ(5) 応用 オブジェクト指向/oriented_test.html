問1：クラスの基礎とインスタンス化

【要件定義：高度医療機器の貸出及び返却・メンテナンス状況追跡システム】
ある総合病院では、各科で共有する非常に高価な医療用検査機器（MRIコイル、特殊超音波プローブなど）の貸出管理を厳密に行うため、新たなオブジェクト指向ベースのシステムを導入することになった。本システムにおける中核を担うのが、各機器の貸出状態および使用料金、そして規定日数を超過した際のペナルティ加算を管理する「MedicalDevice」クラスである。

各インスタンスは生成時に、機器ID（deviceIdentifier）、規定の基本貸出可能日数（normalRentalPeriod）、1日あたりの基本使用料金（baseDailyRentalFee）、および規定日数を1日でも超過した場合に超過日数分に乗算されるペナルティ係数（penaltyMultiplier）を初期化する。貸出処理が行われると、メンバ変数 `isCurrentlyRented` が `true` に設定される。
今回開発部門から依頼されたのは、使用後の機器がシステムに返却された際に呼び出されるメソッド `returnDeviceAndCalculateFee(整数型: returnedDays)` の実装である。
このメソッドは、引数として「実際に機器が借りられていた総日数（returnedDays）」を受け取る。まず、機器の貸出状態フラグを確実に「貸出されていない状態」へと更新しなければならない。その後、基本料金と、もし規定日数をオーバーしていればそのオーバーした日数分のペナルティ料金を合算し、最終的な請求金額を算出して返す仕様となっている。ただし、規定日数以内に返却された場合（returnedDays が normalRentalPeriod 以下の場合）は、実際に借りていた日数分のみの基本料金を計算するのではなく、一律で「normalRentalPeriod日分」の基本料金が最低保証額として請求される特殊な契約形態となっている点に十分に留意すること。実装担当者が記述したコードの空欄を正しく埋め、仕様通りの挙動を完成させよ。

設問

プログラム中の空欄【 a 】および【 b 】に入れるべき正しいコードの組み合わせを、解答群の中から選べ。

  • ア： 【 a 】 isCurrentlyRented = false 【 b 】 overdueDays ≧ 0
  • イ： 【 a 】 isCurrentlyRented ← false 【 b 】 overdueDays ＞ 0
  • ウ： 【 a 】 isCurrentlyRented = false 【 b 】 returnedDays ＞ 0
  • エ： 【 a 】 isCurrentlyRented ← false 【 b 】 returnedDays ＞ 0
  • オ： 【 a 】 isCurrentlyRented ← true 【 b 】 overdueDays ＞ 0
  • カ： 【 a 】 isCurrentlyRented ← false 【 b 】 overdueDays ＜ 0
  • キ： 【 a 】 isCurrentlyRented = true 【 b 】 overdueDays ＞ normalRentalPeriod
  • ク： 【 a 】 isCurrentlyRented ← false 【 b 】 overdueDays ≧ normalRentalPeriod

正解：イ

・【 a 】について：要件には「機器の貸出状態フラグを確実に『貸出されていない状態』へと更新しなければならない」とある。FEの擬似言語において、変数への代入は必ず「←」を用いるため、比較演算子である「=」を使用している選択肢（ア、ウ、キ）は構文エラーとなる。また状態を「貸出されていない（false）」にする必要があるため、「← true」としているオも誤り。正しくは `isCurrentlyRented ← false` である。

よって、両方を正しく満たすのは「イ」となる。

【要件定義：次世代クラウドサーバーリソースの課金計算エンジン】

問3：多態性（ポリモーフィズム）

【要件定義：スマートシティ構想におけるマルチモーダル交通機関の決済・マイレージ統合管理システム】
ある自治体が推進するスマートシティプロジェクトにおいて、バス・地下鉄・シェアサイクル等あらゆる交通手段を単一のインターフェースで統合処理するIC決済システムが開発されている。このシステムでは、全ての乗車パスが「TransitPass」インターフェースを実装しており、改札通過時に呼び出し元システムは具体的なパスの種類を意識することなく `processRideTransaction(整数型: distance)` を実行し、ポリモーフィズム（多態性）を活用して処理を進行させる。

一般市民向けの「CommuterPass」クラスは、乗車距離（distance）を100で割った商をそのまま「mileagePoints」に加算するだけのシンプルな状態更新を行う。
一方で、観光客誘致のために特別に発行される「PremiumTouristPass」クラスは独自の強力な還元ロジックを保持している。このクラスでは、生成時にボーナス倍率（bonusMultiplier）と、特別付与が発生する距離閾値（bonusThreshold）が設定される。乗車処理が行われると、まず「乗車距離を100で割った商にボーナス倍率を掛けた値」を算出して保有ポイントに加算する。さらに、今回の乗車距離がボーナス閾値（bonusThreshold）以上であった場合には、追加で一律50ポイントを保有ポイントに上乗せする仕様となっている。呼び出し元のシステムは全く同じメソッドを実行しているにもかかわらず、オブジェクトの型によって内部状態の変化量が劇的に異なるこの振る舞いを実装したコードにおいて、空欄【 a 】を正確に埋めよ。

  • ウ： mileagePoints ← mileagePoints + (distance ÷ 100 の商) + bonusMultiplier
  • エ： mileagePoints ← mileagePoints + ((distance ÷ 100 の商) × bonusMultiplier)

問4：再帰関数

【要件定義：巨大複合企業のグローバルサプライチェーンにおける部品在庫の深さ優先再帰探索モジュール】
世界中に拠点を展開する製造業のメガコーポレーションにおいて、特定の製造ロットで発覚した重篤な欠陥部品（Defective Part）の現在庫を、全世界の倉庫ネットワークから一斉に割り出して集計する特命プロジェクトが発足した。各地域の保管拠点はツリー構造を形成しており、「WarehouseNode」クラスとして表現される。各ノードは、自身に直接保管されている部品の配列（partsList）と、自身の管轄下にある下位の倉庫ノードの配列（childWarehouses）をメンバ変数として保持している。部品オブジェクト（Partクラス）は、論理型の変数 `isDefective` を持ち、これが `true` であれば欠陥品とみなされる。

システム監査部門が実装した再帰関数 `calculateTotalDefectiveParts(WarehouseNode: currentNode)` は、ツリーの頂点となるルート倉庫から呼び出され、全ての末端倉庫に至るまで欠陥品の数をカウントアップして総合計を返す極めて重要なロジックである。
処理の第一段階として、関数はまず「currentNode」直属の `partsList` をループ走査し、欠陥品の数を変数 `totalDefectives` に集計する。ここまでは正常に記述されているが、第二段階である「下位の倉庫を再帰的に探索し、その戻り値を自身の集計値に合算して最終結果を組み立てる」ためのループ処理内の一部が欠損している。下位倉庫の構造はどこまで深く続いているか予測不可能なため、この空欄【 a 】を再帰呼び出しによって正しく機能するように補完せよ。

  • ア： totalDefectives ← calculateTotalDefectiveParts(currentNode.childWarehouses[i])
  • イ： totalDefectives ← totalDefectives + calculateTotalDefectiveParts(currentNode.partsList[i])
  • ウ： totalDefectives = totalDefectives + calculateTotalDefectiveParts(currentNode.childWarehouses[i])
  • エ： return totalDefectives + calculateTotalDefectiveParts(currentNode.childWarehouses[i])
  • オ： totalDefectives ← totalDefectives + calculateTotalDefectiveParts(currentNode.childWarehouses[i])

・したがって、正しく再帰呼び出しを行い、既存の合計に累積加算している「オ」が唯一の正解である。

問6：リスト構造とオブジェクト操作の応用

【要件定義：大容量ネットワークルータにおけるQoS（Quality of Service）対応パケットスケジューリングキューの割り込み挿入アルゴリズム】
通信キャリアの基幹ネットワーク網で使用される最上位コアルータにおいて、膨大なデータパケットの転送順序を制御するキューイングモジュールのファームウェア改修が行われている。このモジュールでは、各パケットは「Packet」クラスのインスタンスとして表現され、メンバ変数として「高優先度パケット（VoIP音声データや緊急通信など）」であることを示す論理型フラグ `isHighPriority` を保持している。ルータ内部の転送待機バッファは「queue」という1次元配列で表現されており、現在キューに入っている最後のパケットのインデックスが変数 `tail` で管理されている。

今回実装を要求されているのは、新たに到達した高優先度パケットをキューに登録する専用手続 `enqueueHighPriorityPacket` である。
通常のパケットであれば単に `tail` を1増やして配列の末尾に格納すればよいが、高優先度パケットの場合は「現在キュー内で待機している全てのパケットを1つずつ後ろ（インデックスが大きい方）へ強制的にシフト（移動）させ、空いた先頭（インデックス1）に自身を割り込ませて挿入する」という強引な優先処理を行わなければならない（※今回の要件では、既に別の高優先度パケットが存在するかどうかは考慮せず、常に絶対的な先頭であるインデックス1を奪い取る仕様とする）。
この「配列内の既存要素を後ろにずらす」操作を安全に完了させるための、ループ処理内の空欄【 a 】に入る適切な代入式を特定せよ。なお、要素を上書きによって消滅させてしまうデータロストが絶対に発生しないように、シフトする方向と順序に最新の注意を払うこと。

クラス Packet public: 論理型: isHighPriority 手続: enqueueHighPriorityPacket(Packetの配列: queue, 整数型: tail, Packet: vipPacket) 整数型: i /* キュー内の既存パケットを、最後尾のものから順に1つ後ろのインデックスへ移動させる */ for (i を tail から 1 まで 1 ずつ減らす) 【 a 】 endfor /* 空いた先頭に高優先度パケットを挿入し、キューの末尾インデックスを更新する */ queue[1] ← vipPacket tail ← tail + 1

設問

プログラム中の空欄【 a 】に入れるべき正しいコードを、解答群の中から選べ。

  • ア： queue[i] ← queue[i + 1]
  • イ： queue[i + 1] = queue[i]
  • ウ： queue[i + 1] ← queue[i]
  • エ： queue[i] ← queue[i - 1]
  • オ： queue[i - 1] ← queue[i]
  • カ： queue[tail + 1] ← queue[i]
  • キ： queue[i + 1] ← vipPacket
  • ク： queue[1] ← queue[i]

正解：ウ

・要件では、配列内の要素を「1つ後ろ（インデックスが大きい方）へシフト」する必要がある。
・ループは `i` を `tail` から 1 に向かって「減らしながら」進行する。つまり、最後尾の要素から順に操作を行う。
・`i` 番目にある要素を、その後ろである `i + 1` 番目の場所に移動（代入）させるため、コードは `queue[i + 1] ← queue[i]` となる。
・アの `queue[i] ← queue[i + 1]` は、前方にシフトする処理であり、かつループを後ろから回しているため、まだ移動させていない未知の領域（tail+1）の空データを既存のパケットに上書きして破壊してしまう。
・エやオは、インデックスが `i - 1` となっており、前方へずらす処理の誤記である。
・イはFEの代入演算子「←」ではなく比較演算子「=」を用いているため構文エラーとなる。
・したがって、正しく後ろへのシフト代入を行っている「ウ」が正解である。
