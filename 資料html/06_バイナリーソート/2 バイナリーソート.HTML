【科目B対策】2分探索（バイナリサーチ）の完全理解

アルゴリズムの中で最も重要かつ頻出の「2分探索（バイナリサーチ）」。
まずは「High & Low」のような数字当てゲームの感覚で動きを理解し、その後に本番形式のプログラムと照らし合わせてみましょう。

テーマ：数字当てゲーム（動きのシミュレーション）

5つの箱に小さい順に数字が入っています。この中から「70」を探し出します！
配列： [10, 30, 50, 70, 90] （要素番号は1〜5）

2分探索のたった1つのルール

「真ん中を開けて比べる。探している数より小さければ左半分を捨て、大きければ右半分を捨てる。」
これを繰り返して、探索範囲をどんどん半分に狭めていきます。

【1回目】 探す範囲：1番目〜5番目

  • 左の指(low)は1、右の指(high)は5。
  • 真ん中(middle)の場所を計算： (1 + 5) ÷ 2 = 3番目。
  • 3番目を開けると「50」。探している「70」より小さい！
  • 「50」とそれより左はもう見なくていいので、左の指(low)を真ん中の右隣（4番目）にズラす。
  • 結果： [×, ×, × | 70, 90]
    （探索範囲が一気に右半分に絞られました！）

【2回目】 探す範囲：4番目〜5番目

  • 左の指(low)は4、右の指(high)は5。
  • 真ん中(middle)の場所を計算： (4 + 5) ÷ 2 = 4.5 → 小数点切り捨てで4番目。
  • 4番目を開けると「70」。探している「70」とピッタリ一致！
  • 結果： [×, ×, × | 70, 90]
    （発見したので探索終了。答えとして「4番目」を返します。）

※もし探している数字が存在しない場合、最終的に「左の指(low)」が「右の指(high)」を追い越してしまい、範囲が消滅します。これが「見つからなかった（-1を返す）」合図になります。

本番形式：2分探索の擬似言語

実際の「科目B」のフォーマットに合わせて書き起こしました。どこで何をしているのか、横の解説（コメント）を添えて読んでみてください。

  • 配列 data には、あらかじめ小さい順（昇順）に数字が並んでいるとします。
  • 配列の要素番号（インデックス）は 1 から始まります。
// 変数の準備
〇整数型の配列: data
〇整数型: target          // 探したい数字
〇整数型: low, high, middle // 左の指、右の指、真ん中の指
〇整数型: ans             // 見つかった場所を入れる箱（結果）

low ← 1                   // 最初は一番左端（1番目）にセット
high ← dataの要素数       // 最初は一番右端（最後尾）にセット
ans ← -1                  // 見つからなかった場合の初期値として -1 を入れておく

// 【探索のループ】探索範囲がなくなる（lowがhighを追い越す）まで続ける
while (low <= high)
    
    // 【真ん中を決める】
    // (low + high) を 2 で割った「商（端数切り捨て）」を真ん中にする
    middle ← (low + high) ÷ 2 の商
    
    // ① ピッタリ見つかった場合！
    if (data[middle] == target)
        ans ← middle        // 見つかった場所（middle）を結果に保存
        break               // 探索完了！ループを強制的に抜ける
        
    // ② 探している数が、真ん中より「大きい」場合（右半分を探す）
    elseif (data[middle] < target)
        low ← middle + 1    // 左の指(low)を、真ん中の1つ右にズラす
        
    // ③ 探している数が、真ん中より「小さい」場合（左半分を探す）
    else
        high ← middle - 1   // 右の指(high)を、真ん中の1つ左にズラす
        
    endif
endwhile

// ループ終了後、ans には「見つかった場所」か「-1（ない）」が入っている

本番の試験で「穴埋め」にされるポイント

試験では、このプログラムのどこかが「空欄（ [　a　] など）」になっていて、そこに入る式を選ばせる問題が頻出します。特に狙われるのは、以下の3箇所です。ここだけ理解していれば確実に点が取れます。

狙われるポイント①：while文のループ継続条件

空欄の例
while ( [　a　] )
正解
low <= high
なぜ？
探索範囲が存在している間は探し続けます。もし探している数字が存在しない場合、範囲を狭めていくうちに、最終的に左の指（low）が右の指（high）を追い越してしまいます（low > high になる）。この「追い越した瞬間＝もう探す場所がない」という状態になったらループを強制終了させなければならないためです。

狙われるポイント②：真ん中（middle）の計算式

空欄の例
middle ← [　b　] の商
正解
(low + high) ÷ 2
なぜ？
現在の探索範囲における「ちょうど真ん中」の場所を求めるためです。端と端を足して2で割ることで、中心のインデックス（要素番号）を割り出します。

狙われるポイント③：探索範囲を狭める式（指のズラし方）

空欄の例
elseif (data[middle] < target)
    low ← [　c　]
正解
middle + 1
なぜ？
探している数字（target）が、いま見た真ん中の数字（data[middle]）よりも大きいと分かったからです。つまり、真ん中より「左側」には絶対に答えはありません。したがって、新しい探索範囲のスタート地点（low）を、「いま見た真ん中（middle）の1つ右」に更新してあげる必要があります。
（※逆に左半分を探す場合は high ← middle - 1 が正解になります）

この形のプログラムを見たら、「あ、whileで挟み撃ちにして、真ん中と比べて +1 と -1 で範囲を半分に削っている！2分探索だ！」 と瞬時に見抜けるようになります。
バブルソートと合わせて、この2分探索の「見た目の形」を頭の片隅に置いておけば、科目Bのアルゴリズム問題で大きな得点源になりますよ！
