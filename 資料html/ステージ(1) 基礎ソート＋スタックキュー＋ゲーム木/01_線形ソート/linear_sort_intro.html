【科目B対策】線形探索法（リニアサーチ）

アルゴリズムの基本中の基本。先頭から順番に1つずつ調べていく、最もシンプルで直感的な探索方法です。
データがバラバラに並んでいても使えるのが強みですが、後ろの方に答えがあると時間がかかってしまいます。

テーマ：先頭から順番に箱を開けていく

5つの箱の中から「70」を探し出します！
配列： [30, 50, 10, 70, 90] （データはバラバラでOK）

線形探索のたった1つのルール

「左端（1番目）から順番に『これ探してるやつ？』と確認する。見つかったらそこで終了。最後まで見つからなかったら『なし』と報告する。」

【1回目】 1番目の箱を見る

  • 1番目を見る： [30, 50, 10, 70, 90]
  • 探している「70」と違うので、次へ進む。

【2回目】 2番目の箱を見る

  • 2番目を見る： [30, 50, 10, 70, 90]
  • 探している「70」と違うので、次へ進む。

【3回目】 3番目の箱を見る

  • 3番目を見る： [30, 50, 10, 70, 90]
  • 探している「70」と違うので、次へ進む。

【4回目】 4番目の箱を見る

  • 4番目を見る： [30, 50, 10, 70, 90]
  • 探している「70」と一致した！
  • 「4番目にありました！」と報告して、探索を終了します。

本番形式：線形探索の擬似言語

非常にシンプルです。forループで先頭から最後まで順番に回し、if文で一致するかどうかを確認するだけです。

  • 配列 data にはバラバラの数字が入っています。
  • 配列の要素番号（インデックス）は 1 から始まります。
// 変数の準備
〇整数型の配列: data
〇整数型: target          // 探したい数字
〇整数型: i               // 今見ている場所（インデックス）
〇整数型: ans             // 見つかった場所を入れる箱

ans ← -1                  // 見つからなかった場合の初期値として -1 をセット

// 【探索のループ】先頭（1番目）から最後（要素数）まで順番に見ていく
for (i を 1 から dataの要素数 まで 1 ずつ増やす)
    
    // もし、今見ている箱の中身が、探している数字と同じなら…
    if (data[i] == target)
        ans ← i           // 見つけた場所を ans にメモする
        break               // もう探す必要はないので、ループを強制終了！
    endif
    
endfor

// ループ終了後、ans には「見つかった場所」か「-1（ない）」が入っている

本番の試験で「穴埋め」にされるポイント

線形探索そのものは簡単すぎるため、試験では「少し工夫を加えた形（番兵法など）」で出題されることがよくあります。

狙われるポイント①：ループの終了条件

空欄の例
for (i を 1 から [　a　] まで)
正解
dataの要素数
なぜ？
配列の先頭から「一番最後（末尾）」まで漏れなく確認する必要があるからです。最後まで見て見つからなければ「存在しない」ことが確定します。

狙われるポイント②：見つけた後の処理

空欄の例
ans ← i
[　b　]
正解
break
なぜ？
見つかったのに最後までループを回し続けるのは無駄です。break を使ってループから脱出（強制終了）することで、処理を高速化させます。

🔥 発展・超頻出：番兵法（ばんぺいほう）

解説
通常の線形探索（while文で書く場合）は、「①データが一致したか？」と「②配列の最後まで来てしまったか？」の2つを毎回チェックするため、少し効率が悪いです。
そこで、「配列の一番最後に、探している数字（target）を強制的に追加（これを番兵と呼ぶ）」しておきます。こうすれば絶対にどこかで一致するので、「配列の最後まで来てしまったか？」のチェックを省略でき、プログラムが少し速くなります。試験でめちゃくちゃよく出るテクニックです！

【試験で1秒で見抜くコツ】
for文やwhile文を使って、配列を「1ずつ増やしながら（i + 1）」順番に見ていき、一致したら break するコードを見たら、それは「線形探索」です。
また、配列の末尾に探している値を追加する処理（data[N + 1] ← target）を見たら、それは「線形探索（番兵法）」です！
