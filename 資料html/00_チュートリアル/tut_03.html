03 トレース実践② 関数呼び出しのネストと「行き帰り」の法則

ステップ3では、試験で非常によく出る「関数（手続き）のネスト（入れ子）呼び出し」を攻略します！
プログラムが別の関数を呼び出すと、実行場所が別の場所にワープします。そして、呼び出された関数が return（戻り値） を返した瞬間に、元の場所へ逆戻りします。この「行って、戻ってくる」流れを紙の上で正確に整理する方法を学びましょう。

1手続き: main()
2    文字列型: result ← ""
3    result ← procA("1")
4    出力(result)
5
6文字列型: procA(文字列型: s)
7    文字列型: temp ← procB(s)
8    return temp + "A"
9
10文字列型: procB(文字列型: s)
11    return "B" + s + "C"
12選択肢
13ア. 1BCA
14イ. B1CA
15ウ. AB1C
16エ. B1AC

関数のワープを追いかける実況トレース

【1】 すべての大元、main() からスタート！

プログラムは main() から動き出します。2行目で result という空の箱を作ったあと、3行目で procA("1") を呼び出しています。
ここでプログラムは実行を一時ストップし、「"1"」というお土産（引数）を持って、6行目の procA へワープします。

⏳ 現在の関数の重なり状態（下にあるほど待機中）：
▶ main() [3行目で一時停止中・procAの結果待ち]

【2】 procA にワープ！さらに奥へ潜る

6行目の procA に到着しました。渡された引数 s の中身は "1" です。
次に7行目を見ると、なんと temp ← procB(s) とあり、さらに別の関数 procB を呼び出しています！
ここでも procA は一時停止し、「"1"」を持って、さらに10行目の procB へ深くもぐりこみます。

⏳ 現在の関数の重なり状態：
▶ procA(s="1") [7行目で一時停止中・procBの結果待ち]
main() [一時停止中]

【3】 一番奥底の procB を実行 ＆ 初めての脱出（リターン）

10行目の procB に辿り着きました。ここでの引数 s も "1" です。
11行目の return "B" + s + "C" を計算します。文字を合体させると "B" + "1" + "C" = "B1C" になります。
return が発動したため、procBの仕事はこれで終了です！
お土産として確定した文字列 "B1C" を抱えて、呼び出し元だった procA の7行目へと逆戻りします。

⏳ 現在の関数の重なり状態：
⚙️ procB(s="1") ─── 計算結果: "B1C" を持って戻る ➔
procA(s="1") [待機中]
main() [待機中]

【4】 procA が再開！最後の文字合体

7行目の procA に戻ってきました！待機していた temp の中に、さっき戻ってきた "B1C" が無事に入ります。
続く8行目で return temp + "A" を実行します。現在の temp は "B1C" なので、合体させると "B1C" + "A" = "B1CA" になります。
仕事が終わったので、この "B1CA" を持って、最初の大元である main() の3行目へと戻っていきます。

⏳ 現在の関数の重なり状態：
⚙️ procA(s="1") ─── temp("B1C") + "A" = "B1CA" を持って戻る ➔
main() [待機中]

【5】 main() に帰還、そして最終出力

ついに main() の3行目に戻ってきました！戻り値の "B1CA" が変数 result に代入されます。
最後に4行目の 出力(result) が実行され、画面に B1CA が表示されてプログラム全体が終了します！

🎉 最終的な実行結果：
B1CA

🚨 この問題に潜む「上から下へ読む視線」の罠

人間の目は、コードが上から下に並んでいると、無意識に「Aの処理が終わったあとにBの処理が進む」と思い込んでしまいがちです。その結果、文字の並びにつられて "1BCA" や "AB1C" のような間違った選択肢を選んでしまいます。
しかしトレースをしてみると分かる通り、実際に一番最初に計算が完了して文字が作られるのは、一番奥底にある `procB` です！
関数のネストに出会ったら、手元の紙の余白に矢印を書き、「どこに潜っていって、何を持ってどこに戻るのか」をドミノ倒しのようにメモしながら逆算していくのが、ケアレスミスを完全に防ぐ最強のテクニックです。
