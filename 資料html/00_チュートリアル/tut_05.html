05 トレース実践④ 繰り返し（while）ループの数理と境界値

ステップ5では、条件を満たしている間ずーーっと同じ処理をぐるぐる繰り返す「while（ワイル）ループ」をマスターします！
ループ処理で最も間違いが多いのが、ループが「いつ始まって、いつピタッと止まるのか」というギリギリの境界の判断です。掛け算や割り算の記号を一切使わずに、引き算だけで割り算の「商」と「余り」を計算するエレガントなコードを使って、頭がこんがらがらないメモの取り方を身につけましょう。

1整数型: val ← 23
2整数型: div ← 7
3整数型: q ← 0
4
5while (val >= div)
6    val ← val - div
7    q ← q + 1
8endwhile
9val =
10q =

ループを1周ずつ追いかける実況トレース

【初期状態】 1〜3行目の実行

変数を用意して初期値を書き込みます。割られる数の val に23、割る数の div に7、そして「何回引き算できたか」を数えるカウンターの q を0にセットしてスタートします。

📝 手元の紙のメモ状態：
val
23
div
7
q
0

【ループ1回目】 最初の関門突破

5行目の while の条件式を判定します。現在の val は23、div は7です。
「23 は 7 以上か？」は正しい（真）ので、ループの内部へと侵入します！
6行目で val ← 23 - 7 = 16 に上書きされ、7行目で q ← 0 + 1 = 1 に上書きされます。

🔄 5行目判定: 23 >= 7 ➔ 真 (True) （ループに突入）
📝 手元の紙のメモ状態：
val
2316
div
7
q
01

【ループ2回目】 23から7が2回引けた状態

8行目の endwhile に達すると、プログラムは再び5行目の条件判定へと自動で巻き戻ります。
現在の val は16です。「16 は 7 以上か？」はまだ正しい（真）ので、2回目のループに入ります。
val ← 16 - 7 = 9 に上書きされ、q ← 1 + 1 = 2 に上書きされます。

🔄 5行目判定: 16 >= 7 ➔ 真 (True) （ループを継続）
📝 手元の紙のメモ状態：
val
169
div
7
q
12

【ループ3回目】 まだまだ引ける！

再び5行目に戻ります。現在の val は9です。「9 は 7 以上か？」も当然正しい（真）ので、3回目のループを実行します。
val ← 9 - 7 = 2 に上書きされ、q ← 2 + 1 = 3 に上書きされます。

🔄 5行目判定: 9 >= 7 ➔ 真 (True) （ループを継続）
📝 手元の紙のメモ状態：
val
92
div
7
q
23

【ループ終了】 4回目の判定でブレーキ！

さあ、3回目の処理が終わって5行目に戻ってきました。ここが最大の集中ポイントです。
現在の val の中身は最新の「2」になっています。
条件式に当てはめると、「2 は 7 以上か？」となり、これは成立しません（偽：False）！
ここでループにブレーキがかかり、プログラムはループ内（6、7行目）を実行せずに、8行目の endwhile のすぐ後ろへと脱出します。

🛑 5行目判定: 2 >= 7 ➔ 偽 (False) ❌（ループ終了、脱出！）
🎯 最終的な変数の値：
val (余り)
2
div
7
q (商)
3

23の中に7は「3回（q）」入っていて、引ききれなかった「2（val）」が余る、という割り算の答えと見事に一致しました！

🚨 ループの条件式「以上(>=)」と「より大きい(>)」の境界値の罠

このタイプのループ問題で最も狙われるのが、不等号が 以上(>=) になっているか、より大きい(>) になっているかという境界値の罠です。
もしこの問題の条件式が while (val が div より大きい) だった場合、もし初期値が val=21, div=7 のようなピッタリ割り切れる数のときに結果がズレてしまいます。残りが 7 になった時、7は7より大きくないためループが止まってしまい、余りが7というおかしな計算になってしまいます。しかし、以上 であれば「7は7以上」なのでもう1回きれいに引くことができます。
暗算だけで「23÷7だから3あまり2ね」と処理するのではなく、最後の1回が回るか回らないかを最新の変数の数字を使って条件式に当てはめて判定するクセをつけましょう。
