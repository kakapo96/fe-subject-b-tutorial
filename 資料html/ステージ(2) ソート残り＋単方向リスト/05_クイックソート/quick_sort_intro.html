科目B対策：クイックソートの仕組みと擬似言語

テーマ：基準を決めて「小さい組」と「大きい組」に分ける

バラバラに並んだ5つの数字を「小さい順（昇順）」に並べ替えます。
最初の配列： [4, 2, 5, 1, 3]

クイックソートのたった1つのルール

「適当な基準値（ピボット）を決め、それより小さいグループと、大きいグループに分ける。分けたグループに対して、さらに同じことを繰り返す（再帰）」

動きのシミュレーション

【1回目の分割】 全体を分ける

  • 現在の配列： [4, 2, 5, 1, 3]
  • 基準値（ピボット）を決めます。ここでは真ん中の 5 とします。（※どれを選んでもOKです）
  • ピボットの「5」より小さい数を左に、大きい数を右に集めます。
  • 結果： [4, 2, 1, 3 | 5 | なし]
    （これで「5」の最終的な位置が確定しました。次は左のグループをさらに分けます。）

【2回目の分割】 左のグループを分ける

  • 対象グループ： [4, 2, 1, 3]
  • 基準値（ピボット）を真ん中付近の 2 とします。
  • 「2」より小さい数を左、大きい数を右に集めます。
  • 結果： [1 | 2 | 4, 3]
    （「2」の位置が確定しました。「1」はもう1人なのでこれも確定です。）

【3回目の分割】 残った右のグループを分ける

  • 対象グループ： [4, 3]
  • 基準値（ピボット）を 4 とします。
  • 「4」より小さい数を左、大きい数を右に集めます。
  • 結果： [3 | 4 | なし]

【完了】 すべて結合する

  • 確定した要素をすべて繋ぎ合わせます。
  • 結果： [1, 2, 3, 4, 5]
    グループの人数が「1人以下」になったら分割終了です。非常にスピーディ（クイック）に並び替わります！

本番形式：クイックソートの擬似言語

クイックソートの最大の特徴は、「関数の中で、自分自身（関数）をもう一度呼び出す（再帰呼び出し）」ことです。この形を見たら一発でクイックソートだと見抜けます。

  • 配列 data には、バラバラの数字が入っているとします。
  • 配列の要素番号（インデックス）は 1 から始まります。
〇整数型の配列: data

// クイックソートを行う関数（left: 範囲の左端, right: 範囲の右端）
関数 quickSort(整数型: left, 整数型: right)
    〇整数型: i, j, pivot, tmp
    
    // 【再帰の終了条件】 分割した範囲が「1個以下」になったら何もしない
    if (left >= right)
        return
    endif
    
    i ← left
    j ← right
    // 範囲の真ん中の要素を基準値（ピボット）にする
    pivot ← data[(left + right) ÷ 2 の商]  
    
    // 【グループ分け】 左(i)と右(j)がぶつかるまで繰り返す
    while (i <= j)
        // 左側から「ピボット以上の数（＝右に持っていくべき数）」を探す
        while (data[i] < pivot)
            i ← i + 1
        endwhile
        
        // 右側から「ピボット以下の数（＝左に持っていくべき数）」を探す
        while (data[j] > pivot)
            j ← j - 1
        endwhile
        
        // 見つかったら、お互いの数字を入れ替える（スワップ）
        if (i <= j)
            tmp ← data[i]
            data[i] ← data[j]
            data[j] ← tmp
            // 入れ替えたら、次へ進む
            i ← i + 1
            j ← j - 1
        endif
    endwhile
    
    // 【再帰呼び出し】 分割された左右のグループに対して、さらに自分自身を呼び出す！
    quickSort(left, j)    // 左側のグループをさらにソート
    quickSort(i, right)   // 右側のグループをさらにソート
    
    return
関数おわり

本番の試験で「穴埋め」にされるポイント

クイックソートは少し複雑に見えますが、試験で狙われるポイントは実は決まっています。

狙われるポイント①：再帰の終了条件

空欄の例
if ([　a　])
    return
正解
left >= right
なぜ？
自分自身を呼び出し続ける（再帰）プログラムには、必ず「ストッパー（終了条件）」が必要です。クイックソートの場合、「分割されたグループの人数が1人以下になったら、もう並べ替える必要がないので終了する」というルールになります。left（左端）が right（右端）と同じ、あるいは追い越してしまった時がその瞬間です。

狙われるポイント②：ピボットとの比較（左側からの探索）

空欄の例
while (data[i] [　b　] pivot)
正解
< （より小さい）
なぜ？
左側（i）からは、「ピボットよりも大きい（右に持っていくべき）おかしなヤツ」を探して進みます。逆に言えば、「ピボットより小さい間は、正しい場所にいるのでスルーして次へ進む（i ← i + 1）」という条件になります。

狙われるポイント③：再帰呼び出しの引数

空欄の例
quickSort([　c　], right)
正解
i
なぜ？
グループ分けのループ（while）が終わったとき、i と j がすれ違って交差しています。その結果、元の範囲は「left から j までの左グループ」と、「i から right までの右グループ」の2つに分かれています。そのため、右グループをソートするための再帰呼び出しのスタート地点は i になります。

【試験で1秒で見抜くコツ】
関数の最後の方で、自分自身の関数名（quickSortなど）を2回連続で呼び出している（左半分と右半分を処理している）のを見たら、それは間違いなく「クイックソート」です！
