問1：線形探索（番兵法と条件付き走査）

某国家機関の機密文書アクセスログシステムにおいて、指定された社員ID（targetId）がシステムにアクセスした履歴があるかを検証する関数 searchTargetId を実装した。この関数は、アクセスした社員IDが格納された配列 employeeIdList の末尾に「番兵（Sentinel）」として探索対象のIDを追加し、配列の境界チェックを省くことで高速化を図っている。この程度の泥臭いトレースで音を上げるようでは、本番の複雑な境界値管理には耐えられない。確実にループの回転数を追跡しろ。

  • employeeIdList（実行前） = {301, 155, 420, 203, 199, 582}
  • targetId = 888
  • 配列のインデックスは 1 から始まる。
○整数型: searchTargetId(整数型の配列: employeeIdList, 整数型: targetId) 整数型: searchIndex ← 1 整数型: totalElements ← employeeIdList の要素数 employeeIdList[totalElements + 1] ← targetId while (employeeIdList[searchIndex] ≠ targetId) searchIndex ← searchIndex + 1 endwhile if (searchIndex ≦ totalElements) return searchIndex else return -1 endif

設問

上記の初期状態において関数 searchTargetId を実行した場合、while ループの継続条件式である (employeeIdList[searchIndex] ≠ targetId) の評価（判定）は合計で何回実行されるか。正しいものを選べ。

  • ア： 4回
  • イ： 5回
  • ウ： 6回
  • エ： 7回
  • オ： 8回
  • カ： 9回
  • キ： 無限ループになる
  • ク： 1回も実行されない

正解：エ

【解説】
配列の初期要素数は 6（totalElements = 6）である。処理の冒頭で番兵が追加されるため、配列は {301, 155, 420, 203, 199, 582, 888} となり、要素数は 7 になる。
ループ内の判定式 employeeIdList[searchIndex] ≠ targetId の評価ごとの推移は以下の通りだ。
・1回目 (searchIndex=1): 301 ≠ 888 は true。searchIndex は 2 になる。
・2回目 (searchIndex=2): 155 ≠ 888 は true。searchIndex は 3 になる。
・3回目 (searchIndex=3): 420 ≠ 888 は true。searchIndex は 4 になる。
・4回目 (searchIndex=4): 203 ≠ 888 は true。searchIndex は 5 になる。
・5回目 (searchIndex=5): 199 ≠ 888 は true。searchIndex は 6 になる。
・6回目 (searchIndex=6): 582 ≠ 888 は true。searchIndex は 7 になる。
・7回目 (searchIndex=7): 888 ≠ 888 は false。ここで while ループを抜ける。
したがって、条件式の評価は合計 7 回行われる。番兵法の基本的な挙動であり、要素数＋1 回の判定が行われることを瞬時に見抜くべきだ。

問2：2分探索（バイナリサーチと境界管理）

全国の物流倉庫に保管されている数百万点の部品の在庫管理システムにおいて、一意の部品コード（昇順に整列済み）から特定の部品が格納されているインデックスを高速に特定する関数 findPartLocation を作成した。2分探索におけるポインタ更新の境界ズレは、無限ループや配列外参照という致命的なシステムクラッシュを引き起こす。コードの挙動を論理的に完全に把握し、正しい式を導き出せ。甘えは許されない。

○整数型: findPartLocation(整数型の配列: partCodeList, 整数型: targetCode) 整数型: leftIndex ← 1, rightIndex ← partCodeList の要素数, middleIndex while ( [ a ] ) middleIndex ← (leftIndex + rightIndex) ÷ 2 の商 if (partCodeList[middleIndex] = targetCode) return middleIndex elseif (partCodeList[middleIndex] ＜ targetCode) [ b ] else [ c ] endif endwhile return -1

設問

プログラム中の空欄 [ a ] 〜 [ c ] に入れる式の正しい組み合わせを解答群の中から選べ。

  • ア： [ a ] leftIndex ≦ rightIndex　[ b ] leftIndex ← middleIndex + 1　[ c ] rightIndex ← middleIndex - 1
  • イ： [ a ] leftIndex ＜ rightIndex　[ b ] leftIndex ← middleIndex + 1　[ c ] rightIndex ← middleIndex - 1
  • ウ： [ a ] leftIndex ≦ rightIndex　[ b ] leftIndex ← middleIndex - 1　[ c ] rightIndex ← middleIndex + 1
  • エ： [ a ] leftIndex ＜ rightIndex　[ b ] leftIndex ← middleIndex　[ c ] rightIndex ← middleIndex
  • オ： [ a ] leftIndex ≦ rightIndex　[ b ] leftIndex ← middleIndex + 1　[ c ] rightIndex ← middleIndex
  • カ： [ a ] leftIndex ≠ rightIndex　[ b ] leftIndex ← middleIndex + 1　[ c ] rightIndex ← middleIndex - 1
  • キ： [ a ] leftIndex ≦ rightIndex　[ b ] rightIndex ← middleIndex - 1　[ c ] leftIndex ← middleIndex + 1
  • ク： [ a ] leftIndex ＜ rightIndex　[ b ] leftIndex ← middleIndex - 1　[ c ] rightIndex ← middleIndex + 1

正解：ア

【解説】
2分探索における探索範囲の管理について問う問題だ。
[ a ]：探索範囲が存在する限りループを続けるため、leftIndex ≦ rightIndex が正しい。要素が1つの場合（leftIndex と rightIndex が同じ値）でも、その要素が探索対象か確認する必要があるため、＜ ではなく ≦ が必須となる。
[ b ] と [ c ]：中央の値 partCodeList[middleIndex] が探索値より小さい場合、探索値は middleIndex より右側に存在するため、左端の leftIndex を middleIndex + 1 に更新する。逆に大きい場合は、右端の rightIndex を middleIndex - 1 に更新する。すでに比較済みの middleIndex を範囲から除外しなければ、値が見つからなかった際に無限ループに陥る。この基本すら押さえていないようでは話にならない。

問3：バブルソート（隣接交換法と最適化）

営業部から提出された日次の売上データ配列 salesDataList を昇順に整列する処理を実装した。このシステムでは、無駄なループ処理によるサーバー負荷を軽減するため、内側のループで一度もデータ交換（スワップ）が発生しなかった場合、既に配列は整列済みであると判断して処理を強制終了する最適化フラグ isSwapped を組み込んでいる。トレースを途中で投げ出すな。指差し確認で配列の変化を追え。

  • salesDataList（実行前） = {55, 23, 89, 12, 45}
  • 配列のインデックスは 1 から始まる。
○手続: sortSalesData(整数型の配列: salesDataList) 整数型: outerIndex, innerIndex, tempValue, listSize ← salesDataList の要素数 論理型: isSwapped for (outerIndex を 1 から listSize - 1 まで 1 ずつ増やす) isSwapped ← false for (innerIndex を 1 から listSize - outerIndex まで 1 ずつ増やす) if (salesDataList[innerIndex] ＞ salesDataList[innerIndex + 1]) tempValue ← salesDataList[innerIndex] salesDataList[innerIndex] ← salesDataList[innerIndex + 1] salesDataList[innerIndex + 1] ← tempValue isSwapped ← true endif endfor if (isSwapped = false) return endif endfor

設問

上記の初期状態において関数 sortSalesData を実行した際、外側のループ（outerIndex のループ）が 2周完了した直後 の配列 salesDataList の並び順として正しいものを選べ。

  • ア： {23, 12, 45, 55, 89}
  • イ： {23, 55, 12, 45, 89}
  • ウ： {12, 23, 45, 55, 89}
  • エ： {23, 12, 55, 45, 89}
  • オ： {12, 23, 55, 45, 89}
  • カ： {23, 45, 12, 55, 89}
  • キ： {12, 45, 23, 55, 89}
  • ク： {55, 23, 12, 45, 89}

正解：ア

【解説】
最適化フラグ付きのバブルソートのトレースだ。愚直に追うしかない。
初期配列：{55, 23, 89, 12, 45} (listSize=5)
◆ outerIndex = 1 のループ (innerIndex は 1 から 4 まで):
・innerIndex=1: 55 > 23 (真)。スワップ実行。配列は {23, 55, 89, 12, 45}。isSwapped=true。
・innerIndex=2: 55 > 89 (偽)。スワップなし。
・innerIndex=3: 89 > 12 (真)。スワップ実行。配列は {23, 55, 12, 89, 45}。
・innerIndex=4: 89 > 45 (真)。スワップ実行。配列は {23, 55, 12, 45, 89}。
1周目完了時点で、最大値 89 が右端に確定する。
◆ outerIndex = 2 のループ (innerIndex は 1 から 3 まで):
・innerIndex=1: 23 > 55 (偽)。スワップなし。
・innerIndex=2: 55 > 12 (真)。スワップ実行。配列は {23, 12, 55, 45, 89}。isSwapped=true。
・innerIndex=3: 55 > 45 (真)。スワップ実行。配列は {23, 12, 45, 55, 89}。
2周目完了時点で、配列は {23, 12, 45, 55, 89} となる。これが正解のアだ。この程度のトレースで混乱しているようでは合格は遠い。

問4：選択ソート（基本選択法とスワップ判定）

製造ラインの品質検査工程において算出された各ロットの不良品率データ defectRateList を昇順に整列する。この関数 optimizeDefectRates では、未整列部分から最小値を探し出して先頭と入れ替えるが、無駄なメモリアクセスを減らすため、「最小値の存在するインデックスが、現在の先頭インデックスと異なる場合のみ」スワップを実行するという条件分岐を組み込んでいる。アルゴリズムの意図を正確に読み取り、正しい条件式を埋めろ。

○手続: optimizeDefectRates(整数型の配列: defectRateList) 整数型: currentTarget, scanIndex, minimumIndex, tempValue, listSize ← defectRateList の要素数 for (currentTarget を 1 から listSize - 1 まで 1 ずつ増やす) minimumIndex ← currentTarget for (scanIndex を currentTarget + 1 から listSize まで 1 ずつ増やす) if ( [ a ] ) minimumIndex ← scanIndex endif endfor if ( [ b ] ) tempValue ← defectRateList[currentTarget] defectRateList[currentTarget] ← defectRateList[minimumIndex] defectRateList[minimumIndex] ← tempValue endif endfor

設問

プログラム中の空欄 [ a ] と [ b ] に入れる条件式の正しい組み合わせを解答群の中から選べ。

  • ア： [ a ] defectRateList[scanIndex] ＞ defectRateList[minimumIndex]　[ b ] minimumIndex = currentTarget
  • イ： [ a ] defectRateList[scanIndex] ＜ defectRateList[minimumIndex]　[ b ] scanIndex ≠ currentTarget
  • ウ： [ a ] defectRateList[scanIndex] ≦ defectRateList[minimumIndex]　[ b ] minimumIndex = currentTarget
  • エ： [ a ] defectRateList[scanIndex] ＜ defectRateList[minimumIndex]　[ b ] minimumIndex ≠ currentTarget
  • オ： [ a ] defectRateList[scanIndex] ＞ defectRateList[minimumIndex]　[ b ] minimumIndex ≠ currentTarget
  • カ： [ a ] defectRateList[scanIndex] ＜ defectRateList[minimumIndex]　[ b ] minimumIndex = scanIndex
  • キ： [ a ] defectRateList[scanIndex] ≧ defectRateList[minimumIndex]　[ b ] minimumIndex ≠ currentTarget

問5：挿入ソート（基本挿入法と要素のシフト）

データセンターのサーバラックに設置された高感度温度センサーから取得した稼働温度データ tempDataList を、昇順に動的整列する関数を実装した。挿入ソートは、比較した要素を「スワップ（交換）」するのではなく、条件を満たす要素群を「後方へシフト（ずらす）」することで空き領域を作り、退避しておいた要素を挿入する手法である。変数の退避とインデックスの増減で頭が混乱しやすい。メモ用紙を使ってでも配列の変化を完璧に追跡しろ。

  • tempDataList（実行前） = {38, 42, 29, 35, 40}
  • 配列のインデックスは 1 から始まる。
○手続: sortTemperatureData(整数型の配列: tempDataList) 整数型: targetIndex, shiftIndex, savedValue, listSize ← tempDataList の要素数 for (targetIndex を 2 から listSize まで 1 ずつ増やす) savedValue ← tempDataList[targetIndex] shiftIndex ← targetIndex - 1 while (shiftIndex ＞ 0 and tempDataList[shiftIndex] ＞ savedValue) tempDataList[shiftIndex + 1] ← tempDataList[shiftIndex] shiftIndex ← shiftIndex - 1 endwhile tempDataList[shiftIndex + 1] ← savedValue endfor

設問

上記の初期状態において関数 sortTemperatureData を実行した際、外側のループ（targetIndex のループ）が 2周完了した直後（つまり targetIndex が 3 の処理が完了した時点）の配列 tempDataList の並び順として正しいものを選べ。

  • ア： {29, 38, 42, 35, 40}
  • イ： {29, 35, 38, 42, 40}
  • ウ： {38, 29, 42, 35, 40}
  • エ： {38, 42, 29, 35, 40}
  • オ： {29, 42, 38, 35, 40}
  • カ： {38, 29, 35, 42, 40}
  • キ： {42, 38, 29, 35, 40}
  • ク： {29, 35, 38, 40, 42}

正解：ア

【解説】
挿入ソートの泥臭いトレースだ。
初期配列：{38, 42, 29, 35, 40} (listSize=5)
◆ targetIndex = 2 の処理 (1周目):
・退避：savedValue = 42, shiftIndex = 1。
・while判定：tempDataList[1](38) > 42 は偽。ループには入らない。
・挿入：tempDataList[2] = 42。
配列は変化せず {38, 42, 29, 35, 40}。
◆ targetIndex = 3 の処理 (2周目):
・退避：savedValue = 29, shiftIndex = 2。
・while判定1：tempDataList[2](42) > 29 は真。tempDataList[3] に 42 を代入（シフト）。shiftIndex は 1 になる。
・while判定2：tempDataList[1](38) > 29 は真。tempDataList[2] に 38 を代入（シフト）。shiftIndex は 0 になる。
・while判定3：shiftIndex > 0 の条件によりループ終了。
・挿入：tempDataList[1] に退避していた 29 を挿入。
2周目完了時点で、配列は {29, 38, 42, 35, 40} となる。変数 savedValue への退避と、配列要素の上書き（シフト）の仕組みを完全に理解していなければ、この変化には追いつけない。

問6：シェルソート（改良挿入法とギャップ縮小）

全国の配送拠点間における距離データ distanceList を昇順に整列する。このシステムでは、ギャップを半減させる一般的なシェルソートではなく、経験則に基づき最適化された定義済みのギャップ配列 gapSequence（例: {5, 3, 1}）を参照してソートを行うアルゴリズムを採用している。離れた要素同士の挿入ソートを正確に記述するためには、インデックスの加減算を完璧にコントロールする必要がある。配列外参照を起こさぬよう、慎重に式を導き出せ。

○手続: sortDeliveryDistances(整数型の配列: distanceList, 整数型の配列: gapSequence) 整数型: gapLoopIndex, targetIndex, shiftIndex, currentGap, savedValue 整数型: listSize ← distanceList の要素数 for (gapLoopIndex を 1 から gapSequence の要素数 まで 1 ずつ増やす) currentGap ← gapSequence[gapLoopIndex] for (targetIndex を currentGap + 1 から listSize まで 1 ずつ増やす) savedValue ← distanceList[targetIndex] shiftIndex ← [ a ] while (shiftIndex ＞ 0 and distanceList[shiftIndex] ＞ savedValue) distanceList[ [ b ] ] ← distanceList[shiftIndex] shiftIndex ← shiftIndex - currentGap endwhile distanceList[ [ b ] ] ← savedValue endfor endfor

設問

プログラム中の空欄 [ a ] と [ b ] に入れる式の正しい組み合わせを解答群の中から選べ。

  • ア： [ a ] targetIndex - 1　[ b ] shiftIndex + currentGap
  • イ： [ a ] targetIndex - currentGap　[ b ] shiftIndex + 1
  • ウ： [ a ] targetIndex - currentGap　[ b ] shiftIndex + currentGap
  • エ： [ a ] targetIndex + currentGap　[ b ] shiftIndex - currentGap
  • オ： [ a ] shiftIndex - currentGap　[ b ] targetIndex + currentGap
  • カ： [ a ] targetIndex - 1　[ b ] shiftIndex + 1
  • キ： [ a ] targetIndex - currentGap　[ b ] shiftIndex
  • ク： [ a ] shiftIndex　[ b ] shiftIndex + currentGap

正解：ウ

【解説】
定義済みギャップを用いたシェルソートのロジックだ。基本は挿入ソートと同じだが、比較対象のインデックスが 1 ではなく currentGap 離れている点に注意する。
[ a ]：挿入ソートでは退避した要素（savedValue）の1つ前の要素から比較を始める。シェルソートにおいて「1つ前」とは「ギャップ分だけ前」を意味するため、shiftIndex の初期値は targetIndex - currentGap となる。
[ b ]：while ループ内で条件を満たした要素を後方へシフト（ずらす）する処理、およびループ終了後に退避した要素を挿入する処理だ。シフト先は現在の shiftIndex からギャップ分だけ後方になるため、shiftIndex + currentGap が正しい。挿入ソート（問5）のロジックの 1 が currentGap に置き換わっただけだ。これに気づけないようでは応用力が足りない。

問7：クイックソート（分割処理とポインタ交差）

全国統一テストにおける数百万人のスコアデータ scoreList を高速に昇順整列する関数を実装した。このロジックは、配列の中央の要素を基準値（ピボット）とし、左右両端からポインタを進めて不適切な要素をスワップする「Hoareの分割方式」を採用している。再帰呼び出しによる暴走を防ぐためにも、初回の分割処理によって配列がどのように変化するかを正確にシミュレートする能力が必須となる。手計算を恐れるな。全て書き出せ。

  • scoreList（実行前） = {60, 85, 40, 75, 30}
  • 引数 leftEdge = 1, rightEdge = 5 として初回呼び出しされる。
  • 配列のインデックスは 1 から始まる。
○整数型: partitionScoreData(整数型の配列: scoreList, 整数型: leftEdge, 整数型: rightEdge) 整数型: pivotValue, leftPointer, rightPointer, tempSwap pivotValue ← scoreList[(leftEdge + rightEdge) ÷ 2 の商] leftPointer ← leftEdge rightPointer ← rightEdge while (true) while (scoreList[leftPointer] ＜ pivotValue) leftPointer ← leftPointer + 1 endwhile while (scoreList[rightPointer] ＞ pivotValue) rightPointer ← rightPointer - 1 endwhile if (leftPointer ≧ rightPointer) return rightPointer endif tempSwap ← scoreList[leftPointer] scoreList[leftPointer] ← scoreList[rightPointer] scoreList[rightPointer] ← tempSwap leftPointer ← leftPointer + 1 rightPointer ← rightPointer - 1 endwhile

設問

上記の初期状態において関数 partitionScoreData を実行し、最初の分割処理が完了した（関数が return された）直後の配列 scoreList の並び順として正しいものを選べ。

  • ア： {30, 85, 40, 75, 60}
  • イ： {30, 40, 85, 75, 60}
  • ウ： {30, 40, 60, 75, 85}
  • エ： {40, 30, 85, 75, 60}
  • オ： {30, 75, 40, 85, 60}
  • カ： {30, 40, 75, 85, 60}
  • キ： {60, 30, 40, 75, 85}
  • ク： {40, 85, 30, 75, 60}

正解：イ

【解説】
クイックソート（Hoare分割）の過酷なトレースだ。
初期配列：{60, 85, 40, 75, 30}
基準値(pivotValue) = scoreList[(1+5)÷2] = scoreList[3] = 40。
◆ 1周目:
・左からの走査: scoreList[1](60) ＜ 40 は偽。leftPointer は 1 で停止。
・右からの走査: scoreList[5](30) ＞ 40 は偽。rightPointer は 5 で停止。
・交差判定: 1 ≧ 5 は偽。
・スワップ: scoreList[1] と scoreList[5] を交換。配列は {30, 85, 40, 75, 60} になる。
・ポインタ更新: leftPointer=2, rightPointer=4。
◆ 2周目:
・左からの走査: scoreList[2](85) ＜ 40 は偽。leftPointer は 2 で停止。
・右からの走査: scoreList[4](75) ＞ 40 は真。rightPointer を 3 に進める。次に scoreList[3](40) ＞ 40 は偽。rightPointer は 3 で停止。
・交差判定: 2 ≧ 3 は偽。
・スワップ: scoreList[2] と scoreList[3] を交換。配列は {30, 40, 85, 75, 60} になる。
・ポインタ更新: leftPointer=3, rightPointer=2。
◆ 3周目:
・左からの走査: scoreList[3](85) ＜ 40 は偽。leftPointer は 3 で停止。
・右からの走査: scoreList[2](40) ＞ 40 は偽。rightPointer は 2 で停止。
・交差判定: 3 ≧ 2 は真。ここでループを抜け、return 2 となる。
最終的な配列は {30, 40, 85, 75, 60} である。ピボット（40）以下の要素が左側に、それより大きい要素が右側に大まかに振り分けられたことがわかるだろうか。この動きを見失う者は、実務のバグ取りで地獄を見ることになる。
