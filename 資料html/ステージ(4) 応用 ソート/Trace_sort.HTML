問1：線形探索（番兵法による条件判定の最適化）

お前たち、配列の端をいちいちチェックするような無駄なコードをいつまで書いているつもりだ？FEでは実行速度を上げるための泥臭い工夫が当然のように問われる。ここでは「番兵法」だ。
社内のセキュリティゲートを通過した社員のID履歴（入退室ログ）を格納した配列 logIds から、特定の社員ID targetId が最後に記録されたインデックスを探索する。配列の終端を超えないかの判定（i ≦ n）をループの継続条件から排除し、条件判定のコストを下げるため、配列の末尾の次の位置（n + 1）に探したい値自体を「番兵」として仕込む。見つからなかった場合は -1 を返す。

  • 初期配列 logIds = {105, 112, 108, 120, 115, 130}
  • 検索対象 targetId = 115
○整数型: searchTargetId(整数型の配列: logIds, 整数型: targetId) 整数型: i ← 1 整数型: n ← logIdsの要素数 logIds[n + 1] ← targetId while (logIds[i] ≠ targetId) i ← i + 1 endwhile if (i ≦ n) return i else return -1 endif

設問

上記のプログラムにおいて、searchTargetId({105, 112, 108, 120, 115, 130}, 115) として呼び出した場合、whileループの条件式である logIds[i] ≠ targetId が真偽に関わらず評価（実行）された合計回数として正しいものはどれか。

  • ア： 4回
  • イ： 5回
  • ウ： 6回
  • エ： 7回
  • オ： 8回
  • カ： 3回
  • キ： 2回
  • ク： 9回

正解：イ（5回）

配列のインデックスは1からだ。いい加減覚えろ。
初期の logIds は {105, 112, 108, 120, 115, 130}。要素数 n = 6 だ。 直後の処理で logIds[7] ← 115 が実行され、番兵が置かれる。
ここから泥臭くループを追うぞ。
・1回目：i=1, logIds[1] は 105。 105 ≠ 115 は True。iは2になる。
・2回目：i=2, logIds[2] は 112。 112 ≠ 115 は True。iは3になる。
・3回目：i=3, logIds[3] は 108。 108 ≠ 115 は True。iは4になる。
・4回目：i=4, logIds[4] は 120。 120 ≠ 115 は True。iは5になる。
・5回目：i=5, logIds[5] は 115。 115 ≠ 115 は False。
ここでループを抜ける。評価（判定）自体はFalseと判定された5回目も行われているため、合計5回だ。番兵法の仕組みすら頭で再現できないなら本番で泣くことになるぞ。

問2：2分探索（バイナリサーチにおけるLower Bound探索）

単に見つけるだけの甘い2分探索が出ると思っているのか？本番で問われるのは境界（以上・以下）の厳格な管理だ。見つけたら即終了するとは限らない。
このプログラムは、昇順に整列された商品価格データベース priceList において、指定した予算 targetLimit 「以上」の価格を持つ商品が、「配列のどの位置から出現し始めるか（最初に条件を満たすインデックス）」を特定する関数である。対象が存在しない場合は、挿入すべき新しいインデックスを返す。

  • 初期配列 priceList = {1200, 1500, 1500, 1800, 2100, 2500, 3000, 3200}
  • 検索対象 targetLimit = 1600
○整数型: findLowerBound(整数型の配列: priceList, 整数型: targetLimit) 整数型: left ← 1 整数型: right ← priceListの要素数 整数型: mid while (left ≦ right) mid ← (left + right) ÷ 2 の商 if (priceList[mid] ≧ targetLimit) right ← mid - 1 else left ← mid + 1 endif endwhile return left

設問

上記のプログラムにおいて、findLowerBound({1200, 1500, 1500, 1800, 2100, 2500, 3000, 3200}, 1600) を実行したとする。このとき、プログラムの実行中に mid ← (left + right) ÷ 2 の商 の式が評価（実行）された回数と、最終的な戻り値の組み合わせとして正しいものはどれか。

  • ア： 実行回数 2回, 戻り値 3
  • イ： 実行回数 3回, 戻り値 3
  • ウ： 実行回数 3回, 戻り値 4
  • エ： 実行回数 4回, 戻り値 4
  • オ： 実行回数 4回, 戻り値 5
  • カ： 実行回数 2回, 戻り値 4
  • キ： 実行回数 3回, 戻り値 5
  • ク： 実行回数 5回, 戻り値 4

正解：ウ（実行回数 3回, 戻り値 4）

このアルゴリズムは対象の値と一致しても return mid で逃げずに、条件を満たす最左端の境界を突き詰める。
初期状態：要素数=8。left = 1, right = 8。
・ループ1周目 (1 ≦ 8):
mid = (1 + 8) ÷ 2 の商 = 4 (1回目の実行)
priceList[4] は 1800。 1800 ≧ 1600 は True。
右境界を絞る。right = 4 - 1 = 3
・ループ2周目 (1 ≦ 3):
mid = (1 + 3) ÷ 2 の商 = 2 (2回目の実行)
priceList[2] は 1500。 1500 ≧ 1600 は False。
左境界を押し上げる。left = 2 + 1 = 3
・ループ3周目 (3 ≦ 3):
mid = (3 + 3) ÷ 2 の商 = 3 (3回目の実行)
priceList[3] は 1500。 1500 ≧ 1600 は False。
さらに左境界を押し上げる。left = 3 + 1 = 4
ここで left (4) ≦ right (3) が False になりループ終了。midの計算は3回実行され、戻り値の left は 4 になる。

問3：バブルソート（隣接交換法における交換フラグ最適化）

頭を空っぽにして回すだけのバブルソートなど試験では出ない。無駄な処理を省くための「最適化フラグ」の挙動を追うんだ。
工場のラインから流れてきた製品の重量データが格納された配列 weights を、重い順（降順）に並び替える。内側のループで一度もスワップ（交換）が発生しなかった場合、その時点で「すでに整列済み」と判断して処理を打ち切る論理型変数 swapped を用いている。

  • 初期配列 weights = {45, 52, 48, 60, 58}
○手続: optimizedBubbleSort(整数型の配列: weights) 整数型: i, j, tmp 整数型: n ← weightsの要素数 論理型: swapped for (i を 1 から n - 1 まで 1 ずつ増やす) swapped ← false for (j を 1 から n - i まで 1 ずつ増やす) if (weights[j] ＜ weights[j + 1]) tmp ← weights[j] weights[j] ← weights[j + 1] weights[j + 1] ← tmp swapped ← true endif endfor if (swapped = false) return endif endfor

設問

初期配列 {45, 52, 48, 60, 58} を引数として手続を呼び出した際、外側のループ（変数 i のループ）が「2周目まで完了した直後（i=2 のループ終了時）」における配列 weights の要素の並び順として正しいものはどれか。

  • ア： {52, 60, 58, 48, 45}
  • イ： {52, 48, 60, 58, 45}
  • ウ： {60, 58, 52, 48, 45}
  • エ： {52, 60, 48, 58, 45}
  • オ： {45, 48, 52, 58, 60}
  • カ： {60, 52, 58, 48, 45}
  • キ： {52, 60, 58, 45, 48}
  • ク： {58, 60, 52, 48, 45}

正解：ア（{52, 60, 58, 48, 45}）

配列の更新を順に追う。条件は weights[j] ＜ weights[j + 1] だから、小さいものが右に押し出される「降順ソート」だ。
【i = 1 のループ】 (j は 1 から 4 まで)
・j=1: {45, 52} 比較。45 < 52 はTrue。Swapして {52, 45, 48, 60, 58}
・j=2: {45, 48} 比較。45 < 48 はTrue。Swapして {52, 48, 45, 60, 58}
・j=3: {45, 60} 比較。45 < 60 はTrue。Swapして {52, 48, 60, 45, 58}
・j=4: {45, 58} 比較。45 < 58 はTrue。Swapして {52, 48, 60, 58, 45}
※一番小さい45が右端に確定した。
【i = 2 のループ】 (j は 1 から 3 まで)
・j=1: {52, 48} 比較。52 < 48 はFalse。そのまま。
・j=2: {48, 60} 比較。48 < 60 はTrue。Swapして {52, 60, 48, 58, 45}
・j=3: {48, 58} 比較。48 < 58 はTrue。Swapして {52, 60, 58, 48, 45}
i=2が終了した時点での配列は上記の通りだ。条件式を適当に読み飛ばすと昇順と勘違いして自滅するぞ。

問4：選択ソート（不要な自己代入の省略）

無駄な自己代入（arr[i] と arr[i] をスワップする処理）を平気で書くコードは減点対象だ。実務でもFEでも、無駄なメモリアクセスは悪とみなされる。
各店舗の月間売上データが格納された配列 sales を昇順に整列する。内側のループで最小値を持つインデックス minIdx を特定した後、そのインデックスが探索開始位置 i と異なる場合のみスワップ処理を実行するよう最適化されている。

  • 初期配列 sales = {85, 92, 78, 85, 60, 70}
○手続: optimizedSelectionSort(整数型の配列: sales) 整数型: i, j, minIdx, tmp 整数型: n ← salesの要素数 for (i を 1 から n - 1 まで 1 ずつ増やす) minIdx ← i for (j を i + 1 から n まで 1 ずつ増やす) if (sales[j] ＜ sales[minIdx]) minIdx ← j endif endfor if (minIdx ≠ i) tmp ← sales[i] sales[i] ← sales[minIdx] sales[minIdx] ← tmp endif endfor

設問

初期配列 {85, 92, 78, 85, 60, 70} を引数として手続を呼び出した際、外側のループ（変数 i のループ）が「2周目まで完了した直後（i=2 のループ終了時）」における配列 sales の要素の並び順として正しいものはどれか。

  • ア： {60, 70, 78, 85, 85, 92}
  • イ： {60, 92, 78, 85, 85, 70}
  • ウ： {60, 70, 78, 92, 85, 85}
  • エ： {60, 78, 70, 85, 85, 92}
  • オ： {70, 60, 78, 85, 85, 92}
  • カ： {60, 78, 85, 85, 92, 70}
  • キ： {60, 70, 85, 78, 85, 92}
  • ク： {60, 70, 92, 85, 85, 78}

正解：ア（{60, 70, 78, 85, 85, 92}）

内側の j のループは「一番小さい値のインデックスを探す」処理だ。
【i = 1 のループ】 (探索範囲：要素1〜6)
最小値は 60（インデックス5）。minIdx = 5 となる。
minIdx (5) ≠ i (1) が成立するので、sales[1] と sales[5] をスワップ。
配列は {60, 92, 78, 85, 85, 70} になる。
【i = 2 のループ】 (探索範囲：要素2〜6)
探索対象は {92, 78, 85, 85, 70}。
最小値は 70（インデックス6）。minIdx = 6 となる。
minIdx (6) ≠ i (2) が成立するので、sales[2] と sales[6] をスワップ。
配列は {60, 70, 78, 85, 85, 92} になる。
この程度の変化を追えずにプログラマを名乗る気か？

問5：挿入ソート（要素の退避とシフト処理）

配列の要素を後ろにずらす（シフトする）動作を直感に頼って追うと、インデックスの「+1」と「-1」で確実に破綻するぞ。一時変数 tmp に退避した要素が、空いた隙間のどこに着地するかを冷徹に監視しろ。
このプログラムは、オンライン対戦ゲームのスコアボードに並ぶプレイヤーのレート値配列 rates を、高い順（降順）に整列させる処理である。

  • 初期配列 rates = {1400, 1650, 1500, 1800, 1450}
○手続: insertionSortDesc(整数型の配列: rates) 整数型: i, j, tmp 整数型: n ← ratesの要素数 for (i を 2 から n まで 1 ずつ増やす) tmp ← rates[i] j ← i - 1 while (j ＞ 0 and rates[j] ＜ tmp) rates[j + 1] ← rates[j] j ← j - 1 endwhile rates[j + 1] ← tmp endfor

設問

初期配列 {1400, 1650, 1500, 1800, 1450} を引数として手続を呼び出した際、外側のループ（変数 i のループ）が「2周目まで完了した直後（i=3 のループ終了時）」において、これまでに要素を後ろへずらした（rates[j + 1] ← rates[j] が実行された）合計回数と、その時点の配列 rates の状態の組み合わせとして正しいものはどれか。

  • ア： シフト 1回, {1650, 1400, 1500, 1800, 1450}
  • イ： シフト 2回, {1650, 1400, 1500, 1800, 1450}
  • ウ： シフト 1回, {1650, 1500, 1400, 1800, 1450}
  • エ： シフト 2回, {1650, 1500, 1400, 1800, 1450}
  • オ： シフト 3回, {1650, 1500, 1400, 1800, 1450}
  • カ： シフト 2回, {1650, 1500, 1800, 1400, 1450}
  • キ： シフト 3回, {1500, 1650, 1400, 1800, 1450}
  • ク： シフト 4回, {1650, 1500, 1400, 1800, 1450}

正解：エ（シフト 2回, {1650, 1500, 1400, 1800, 1450}）

降順（大きいものが前）に並べる処理だ。
【i = 2 のループ】
・tmp = rates[2]（1650）、j = 1。
・rates[1](1400) ＜ 1650 (True)。
・rates[2] ← rates[1]（シフト1回目発生。1400が後ろにずれる）、j = 0。
・ループを抜け、rates[1] ← tmp(1650)。
・配列は {1650, 1400, 1500, 1800, 1450} になる。
【i = 3 のループ】
・tmp = rates[3]（1500）、j = 2。
・rates[2](1400) ＜ 1500 (True)。
・rates[3] ← rates[2]（シフト2回目発生。1400が後ろにずれる）、j = 1。
・rates[1](1650) ＜ 1500 (False)。ループ終了。
・rates[2] ← tmp(1500)。
・配列は {1650, 1500, 1400, 1800, 1450} になる。
シフト回数は計2回。値をどこに退避し、インデックスがどう推移するか、紙に書いて視覚化しないと痛い目を見るぞ。

問6：シェルソート（任意のギャップ間隔指定による挿入法）

シェルソートは実質的な3重ループだ。手動トレースが最も破綻しやすいアルゴリズムの一つと肝に銘じろ。
通信パケットの到着順序の再構築のため、配列 packets を昇順に整列する。ギャップ（間隔）は計算で求めるのではなく、あらかじめ設定された配列 gaps に従って段階的に狭めていく。最初のギャップが終わった段階での内部状態を正確に捉えられるか試してやる。

  • 初期配列 packets = {42, 15, 68, 23, 5}
  • ギャップ配列 gaps = {2, 1}
○手続: shellSortWithGaps(整数型の配列: packets, 整数型の配列: gaps) 整数型: i, j, k, h, tmp 整数型: n ← packetsの要素数 for (k を 1 から gapsの要素数 まで 1 ずつ増やす) h ← gaps[k] for (i を h + 1 から n まで 1 ずつ増やす) tmp ← packets[i] j ← i - h while (j ＞ 0 and packets[j] ＞ tmp) packets[j + h] ← packets[j] j ← j - h endwhile packets[j + h] ← tmp endfor endfor

設問

初期配列 {42, 15, 68, 23, 5}、ギャップ配列 {2, 1} を引数として手続を呼び出した際、「1回目の外側ループ（k = 1、すなわちギャップ h = 2 での処理）がすべて完了した直後」における配列 packets の要素の並び順として正しいものはどれか。

  • ア： {42, 15, 68, 23, 5}
  • イ： {15, 42, 23, 68, 5}
  • ウ： {5, 15, 42, 23, 68}
  • エ： {5, 23, 42, 15, 68}
  • オ： {5, 15, 23, 42, 68}
  • カ： {42, 23, 68, 15, 5}
  • キ： {5, 42, 15, 23, 68}
  • ク： {15, 5, 23, 42, 68}

正解：ウ（{5, 15, 42, 23, 68}）

k = 1 のとき、h = 2 だ。つまり、2つ飛ばしの要素同士で挿入ソートを行う。
【h = 2 での i のループ】(i は 3 から 5)
・i = 3 (対象 68)：
tmp = 68。j = 1(対象 42)。42 ＞ 68 はFalse。
移動なし。配列は {42, 15, 68, 23, 5}。
・i = 4 (対象 23)：
tmp = 23。j = 2(対象 15)。15 ＞ 23 はFalse。
移動なし。配列は {42, 15, 68, 23, 5}。
・i = 5 (対象 5)：
tmp = 5。j = 3(対象 68)。68 ＞ 5 はTrue。68を位置5へシフト。j = 1に。
次、j = 1(対象 42)。42 ＞ 5 はTrue。42を位置3へシフト。j = -1に。
空いた位置1に tmp の5を挿入。
配列は {5, 15, 42, 23, 68} になる。
たった1巡目のギャップ処理で、すでに全体がかなり整列に近い形に組み変わったのがわかるだろう。これがシェルソートの強みだ。

問7：クイックソート（両端ポインタ交差方式による分割）

いよいよ最後だ。クイックソートの分割処理（Hoareの分割方式）において、左右から迫るポインタ（i と j）がどのように交差して基準値（ピボット）未満と以上のグループを振り分けるか、その瞬間の配列を切り出せるかを見極める。
膨大なログファイルから抽出したタイムスタンプ配列 times を昇順にソートするため、対象範囲 left から right に対して1回の分割処理を行い、交差したインデックスを返す関数である。

  • 初期配列 times = {35, 12, 48, 22, 50}
  • 呼出引数 left = 1, right = 5
○整数型: partitionHoare(整数型の配列: times, 整数型: left, 整数型: right) 整数型: pivot, i, j, tmp pivot ← times[(left + right) ÷ 2 の商] i ← left j ← right while (true) while (times[i] ＜ pivot) i ← i + 1 endwhile while (times[j] ＞ pivot) j ← j - 1 endwhile if (i ≧ j) return j endif tmp ← times[i] times[i] ← times[j] times[j] ← tmp i ← i + 1 j ← j - 1 endwhile

設問

初期配列 {35, 12, 48, 22, 50} に対して partitionHoare(times, 1, 5) を実行したとする。この関数が戻り値を返して終了した直後（1回目の分割処理完了時）における、配列 times の要素の並び順として正しいものはどれか。

  • ア： {35, 12, 48, 22, 50}
  • イ： {12, 22, 35, 48, 50}
  • ウ： {35, 12, 22, 48, 50}
  • エ： {12, 35, 22, 48, 50}
  • オ： {22, 12, 35, 48, 50}
  • カ： {35, 22, 12, 48, 50}
  • キ： {12, 22, 48, 35, 50}
  • ク： {22, 12, 48, 35, 50}

正解：ウ（{35, 12, 22, 48, 50}）

ピボット（基準値）は times[(1+5)÷2の商] = times[3] = 48 だ。i = 1, j = 5 からスタートする。
【外側 while 1週目】
・times[i] ＜ 48 による i の進行：
35 ＜ 48 (True) → i=2 に進む。
12 ＜ 48 (True) → i=3 に進む。
48 ＜ 48 (False) → iは3で停止。（左側でピボット以上を見つけた）
・times[j] ＞ 48 による j の進行：
50 ＞ 48 (True) → j=4 に進む。
22 ＞ 48 (False) → jは4で停止。（右側でピボット以下を見つけた）
・i(3) ≧ j(4) は False。スワップを実行する。
times[3](48) と times[4](22) を交換。
配列は {35, 12, 22, 48, 50} となる。
その後 i = 4, j = 3 となる。
【外側 while 2週目】
・times[i(4)](48) ＜ 48 は False → iは4で停止。
・times[j(3)](22) ＞ 48 は False → jは3で停止。
・i(4) ≧ j(3) が True となり、return 3 で終了。
この結果、インデックス1〜3が「48以下」、インデックス4〜5が「48以上」のグループに分割された。この1ターンの動きすら追えないなら、再帰呼び出しなど夢のまた夢だ。
