問1：線形探索（番兵法と条件付き走査）

あなたは、巨大な倉庫管理システムにおける商品IDの検索モジュールを設計する担当者です。ハンディスキャナーで読み取った『targetItemId』が、現在システムに登録されている『itemIdList』の中に存在するかどうかを高速かつ確実に判定する必要があります。通常の線形探索ではループのたびに「配列の終端に達したか」の境界チェックを行うため実行オーバーヘッドが嵩みます。これを防ぐため、配列の末尾のさらに一つ後ろの要素に探したい値自体を一時的に「番兵」として配置し、ループの継続条件を簡略化する『番兵法』を採用することにしました。

以下のコードの空欄 [ a ] 〜 [ c ] に入る最も適切な組み合わせを解答群から選びなさい。初期状態の配列の要素数は変数 n に格納されています。

  • 探索対象の配列（itemIdList）: {104, 218, 335, 452, 591, 620, 711}
  • 探したい値（targetItemId）: 899
  • ※配列のインデックスは1から始まります。
○整数型: searchTargetItem(整数型の配列: itemIdList, 整数型: targetItemId) 整数型: i ← 1 整数型: n ← itemIdListの要素数 [ a ] while ([ b ]) i ← i + 1 endwhile if ([ c ]) return i else return -1 endif

設問

空欄 [ a ] 〜 [ c ] に当てはまる記述の組み合わせとして正しいものはどれか。

  • ア： [a] itemIdList[n] ← targetItemId　[b] itemIdList[i] ≠ targetItemId　[c] i ＜ n
  • イ： [a] itemIdList[n + 1] ← targetItemId　[b] itemIdList[i] = targetItemId　[c] i ≦ n
  • ウ： [a] itemIdList[n + 1] ← targetItemId　[b] itemIdList[i] ≠ targetItemId　[c] i ≦ n
  • エ： [a] itemIdList[n] ← targetItemId　[b] itemIdList[i] ≠ targetItemId　[c] i ≦ n
  • オ： [a] itemIdList[n + 1] ← targetItemId　[b] itemIdList[i] ≠ targetItemId　[c] i ＞ n
  • カ： [a] itemIdList[n - 1] ← targetItemId　[b] itemIdList[i] = targetItemId　[c] i ≦ n
  • キ： [a] itemIdList[n + 1] ← targetItemId　[b] itemIdList[i] ≠ targetItemId　[c] i ＜ n
  • ク： [a] itemIdList[n] ← targetItemId　[b] itemIdList[i] = targetItemId　[c] i ≦ n + 1

正解：ウ

【解説】
番兵法は、配列の本来の要素の次（n + 1 の位置）に探索値をあらかじめセットしておくことで、ループ内で「インデックスが要素数を超えていないか」という境界判定を省略する手法です。

1. 空欄[a]：元の要素数が n であるため、番兵を配置するインデックスは n + 1 となります。したがって itemIdList[n + 1] ← targetItemId が入ります。
2. 空欄[b]：目的の値が見つかるまでループを回し続けるため、現在の要素がターゲットと「一致しない間」ループを継続します。よって itemIdList[i] ≠ targetItemId となります。
3. 空欄[c]：ループを抜けたときのインデックス i が、元の要素の範囲内（n以下）であれば配列内に存在した証拠であり、n+1 であれば番兵に引っかかった（元の配列には存在しなかった）ことを意味します。よって発見時の条件式は i ≦ n となります。

実際に今回のテストデータ（n=7, 探す値=899）でトレースすると、899は存在しないため、ループは i=8 の要素（番兵）と一致した時点で終了します。このとき i=8 となり、if (8 ≦ 7) は偽となるため正しく -1 が返されます。

問2：2分探索（バイナリサーチと境界管理）

社内のセキュリティ監査チームから、社員の膨大なアクセスログの中から特定の時刻（秒数換算）にログインした記録を特定するよう緊急の指示を受けました。ログはすでに昇順にソートされているため、あなたは配列の中央値を参照しながら探索範囲を半減させていく『2分探索』アルゴリズムを用いて検索を行います。

今回はテストデータとして抽出された11件の配列 `accessTimeLog` に対して、`targetTime = 14400` を探索します。この関数を実行したとき、whileループ内で中央値 `mid` の計算や判定が行われる回数（変数 calcCount が最終的に return される直前に保持している値）はいくつになるか答えなさい。

  • 探索対象の配列（accessTimeLog）: {3600, 7200, 10800, 14400, 18000, 21600, 25200, 28800, 32400, 36000, 39600}
  • 探したい値（targetTime）: 14400
  • ※配列のインデックスは1から始まり、要素数は11です。
○整数型: binarySearchLog(整数型の配列: accessTimeLog, 整数型: targetTime) 整数型: left ← 1 整数型: right ← accessTimeLogの要素数 整数型: mid, calcCount ← 0 while (left ≦ right) calcCount ← calcCount + 1 mid ← (left + right) ÷ 2 の商 if (accessTimeLog[mid] = targetTime) return mid elseif (accessTimeLog[mid] ＜ targetTime) left ← mid + 1 else right ← mid - 1 endif endwhile return -1

設問

関数内で return 文が実行される直前の、変数 calcCount の値として正しいものはどれか。

  • ア： 1回
  • イ： 2回
  • ウ： 3回
  • エ： 4回
  • オ： 5回
  • カ： 6回
  • キ： 7回
  • ク： 8回

正解：ウ（3回）

【トレース詳細】
初期状態: left=1, right=11, target=14400, calcCount=0

■1周目のループ
left(1) ≦ right(11) は真。
calcCount ← 1
mid = (1 + 11) ÷ 2 = 6
accessTimeLog[6] の値は 21600。
21600 ＞ 14400 のため else に分岐し、right ← 6 - 1 = 5 に更新。

■2周目のループ
left(1) ≦ right(5) は真。
calcCount ← 2
mid = (1 + 5) ÷ 2 = 3
accessTimeLog[3] の値は 10800。
10800 ＜ 14400 のため elseif に分岐し、left ← 3 + 1 = 4 に更新。

■3周目のループ
left(4) ≦ right(5) は真。
calcCount ← 3
mid = (4 + 5) ÷ 2 = 4
accessTimeLog[4] の値は 14400。
14400 = 14400 となり条件に一致。そのまま return mid が実行されて関数を抜けます。

よって、計算および判定が行われた回数（calcCount）は 3 となります。

問3：バブルソート（隣接交換法と最適化）

あなたはECサイトのバックエンド開発チームに所属し、日々蓄積される顧客の購入金額データを金額順（昇順）に整列する処理を実装しています。日々のデータは追加されるたびに粗くソートされているため、配列の大部分は既に整列済みであるという特性を持っています。この特性を活かし、配列全体を1周なめた際に『一度もデータの交換（スワップ）が発生しなかった場合』は、既に完全に整列されていると判断して無駄な処理を打ち切る『最適化バブルソート（フラグ付きバブルソート）』を採用します。

以下のコードの空欄 [ a ] 〜 [ c ] に入る最も適切な組み合わせを解答群から選びなさい。

  • 配列のインデックスは1から始まります。
  • 変数 isSwapped は論理型（true または false）です。
○手続: sortPurchaseData(整数型の配列: purchaseAmounts) 整数型: i, j, tempValue 整数型: n ← purchaseAmountsの要素数 論理型: isSwapped for (i を 1 から n - 1 まで 1 ずつ増やす) [ a ] for (j を 1 から [ b ] まで 1 ずつ増やす) if (purchaseAmounts[j] ＞ purchaseAmounts[j + 1]) tempValue ← purchaseAmounts[j] purchaseAmounts[j] ← purchaseAmounts[j + 1] purchaseAmounts[j + 1] ← tempValue isSwapped ← true endif endfor if ([ c ]) return endif endfor

設問

空欄 [ a ] 〜 [ c ] に当てはまる記述の組み合わせとして正しいものはどれか。

  • ア： [a] isSwapped ← false　[b] n - i　[c] isSwapped = false
  • イ： [a] isSwapped ← true　[b] n - i　[c] isSwapped = false
  • ウ： [a] isSwapped ← false　[b] n - i + 1　[c] isSwapped = true
  • エ： [a] isSwapped ← false　[b] n - i　[c] isSwapped = true
  • オ： [a] isSwapped ← true　[b] n - 1　[c] isSwapped = false
  • カ： [a] isSwapped ← false　[b] n - j　[c] isSwapped = false
  • キ： [a] isSwapped ← false　[b] n - 1　[c] isSwapped = false
  • ク： [a] isSwapped ← true　[b] n - i + 1　[c] isSwapped = true

正解：ア

【解説】
この問題はバブルソートの典型的な最適化手法を問うものです。

1. 空欄[a]：各外側ループ（iのループ）が始まるたびに、その周で交換が発生したかどうかを判定するためのフラグを初期化する必要があります。交換が発生していない状態から始めるため isSwapped ← false をセットします。
2. 空欄[b]：バブルソートは1回の外側ループが終わるごとに、最も大きい要素が配列の末尾に確定して固定されていきます。i回目の外側ループでは、末尾の i 個はすでに整列済みであるため、内側ループの比較上限は n - i までとなります。
3. 空欄[c]：内側ループが全て終わった後、もし isSwapped が false のままであれば、「隣接する要素を比較したが一度も順番が逆転していなかった」ことになり、配列全体のソートが完了していることが保証されます。したがって、早期終了の条件は isSwapped = false となります。

これらを満たす組み合わせはアです。

問4：選択ソート（基本選択法とスワップ判定）

工場の製品ラインにおける不良率データを昇順に並べ替えるシステムを開発しています。システムに組み込まれているフラッシュメモリは書き込み回数に寿命があるため、配列の書き換え（スワップ）を最小限に抑える必要があります。そこで、未整列部分から最小値のインデックスを探したのち、それが「現在のインデックスと同じであれば無駄な自己代入を行わない」という条件分岐を追加した改良型選択ソートを用います。

以下の初期配列 `defectRates` をこのアルゴリズムでソートしたとき、『外側の for ループ（変数 i のループ）が 2周 完了した直後』の配列の並び順として正しいものを選びなさい。

  • 初期状態の配列（defectRates）: {4, 1, 5, 2, 3}
  • ※配列のインデックスは1から始まり、要素数は5です。
○手続: sortDefectRates(整数型の配列: defectRates) 整数型: i, j, minIdx, tempValue 整数型: n ← defectRatesの要素数 for (i を 1 から n - 1 まで 1 ずつ増やす) minIdx ← i for (j を i + 1 から n まで 1 ずつ増やす) if (defectRates[j] ＜ defectRates[minIdx]) minIdx ← j endif endfor if (minIdx ≠ i) tempValue ← defectRates[i] defectRates[i] ← defectRates[minIdx] defectRates[minIdx] ← tempValue endif endfor

設問

外側の for ループが2周完了した直後の配列の状態はどれか。

  • ア： {1, 2, 3, 4, 5}
  • イ： {1, 4, 5, 2, 3}
  • ウ： {1, 2, 5, 4, 3}
  • エ： {1, 4, 2, 5, 3}
  • オ： {4, 1, 2, 5, 3}
  • カ： {1, 2, 4, 5, 3}
  • キ： {2, 1, 5, 4, 3}
  • ク： {1, 5, 4, 2, 3}

正解：ウ

【トレース詳細】
初期状態：defectRates = {4, 1, 5, 2, 3}

■外側1周目 (i = 1)
minIdx は初期値 1。未整列部分はインデックス 2〜5。
j=2: defectRates[2]=1 は defectRates[1]=4 より小さいため minIdx ← 2 に更新。
j=3: defectRates[3]=5 は小さくない。
j=4: defectRates[4]=2 は小さくない。
j=5: defectRates[5]=3 は小さくない。
ループ終了時 minIdx は 2。minIdx(2) ≠ i(1) なのでスワップ実行。
arr[1] と arr[2] を交換し、配列は {1, 4, 5, 2, 3} に変化。

■外側2周目 (i = 2)
minIdx は初期値 2。未整列部分はインデックス 3〜5。
j=3: defectRates[3]=5 は defectRates[2]=4 より小さくない。
j=4: defectRates[4]=2 は defectRates[2]=4 より小さいため minIdx ← 4 に更新。
j=5: defectRates[5]=3 は defectRates[4]=2 より小さくない。
ループ終了時 minIdx は 4。minIdx(4) ≠ i(2) なのでスワップ実行。
arr[2] と arr[4] を交換し、配列は {1, 2, 5, 4, 3} に変化。

これにより、2周完了直後の並び順はウとなります。

問5：挿入ソート（基本挿入法と要素のシフト）

あなたはIoTデバイスから断続的に送られてくる温度センサーのストリームデータを受け取り、随時データベース上で昇順に保つための処理モジュールを記述しています。データが追加されるたびに、未整列部分の先頭要素を `tempValue` に退避し、整列済み部分を後ろから前へ順に比較して、より大きい要素を一つ後ろへずらす（シフトする）ことで適切な位置を空け、そこにデータを挿入する『挿入ソート』を実装します。

以下のコードの空欄 [ a ] 〜 [ c ] に入る最も適切な組み合わせを解答群から選びなさい。

  • 配列のインデックスは1から始まります。
  • 変数 tempValue には挿入対象となる値が一時的に保持されます。
○手続: sortSensorData(整数型の配列: sensorData) 整数型: i, j, tempValue 整数型: n ← sensorDataの要素数 for (i を 2 から n まで 1 ずつ増やす) tempValue ← sensorData[i] j ← i - 1 while ([ a ]) [ b ] j ← j - 1 endwhile [ c ] endfor

設問

空欄 [ a ] 〜 [ c ] に当てはまる記述の組み合わせとして正しいものはどれか。

  • ア： [a] j ＞ 0 and sensorData[j] ＞ tempValue　[b] sensorData[j] ← sensorData[j - 1]　[c] sensorData[j + 1] ← tempValue
  • イ： [a] j ≧ 0 and sensorData[j] ＞ tempValue　[b] sensorData[j + 1] ← sensorData[j]　[c] sensorData[j] ← tempValue
  • ウ： [a] j ＞ 0 and sensorData[j] ＜ tempValue　[b] sensorData[j + 1] ← sensorData[j]　[c] sensorData[j + 1] ← tempValue
  • エ： [a] j ＞ 0 and sensorData[j] ＞ tempValue　[b] sensorData[j + 1] ← sensorData[j]　[c] sensorData[j + 1] ← tempValue
  • オ： [a] j ＞ 1 and sensorData[j] ＞ tempValue　[b] sensorData[j + 1] ← sensorData[j]　[c] sensorData[j] ← tempValue
  • カ： [a] j ＞ 0 and sensorData[j] ＞ tempValue　[b] sensorData[j + 1] ← tempValue　[c] sensorData[j + 1] ← sensorData[j]
  • キ： [a] j ≧ 1 and sensorData[j] ＜ tempValue　[b] sensorData[j + 1] ← sensorData[j]　[c] sensorData[j + 1] ← tempValue
  • ク： [a] j ＞ 0 and sensorData[j + 1] ＞ tempValue　[b] sensorData[j + 1] ← sensorData[j]　[c] sensorData[j] ← tempValue

正解：エ

【解説】
挿入ソートの根幹をなす要素シフト処理のロジックです。

1. 空欄[a]：配列の境界外参照を防ぐため、比較対象のインデックス j は 1 以上である必要があります。また、昇順に整列するため、現在の比較対象要素 `sensorData[j]` が挿入したい値 `tempValue` よりも「大きい」間ループを継続します。よって j ＞ 0 and sensorData[j] ＞ tempValue となります（FEの配列は1始まりのため j > 0 です）。
2. 空欄[b]：より大きい要素を見つけたため、その要素を一つ後ろのスペースに移動（シフト）させます。代入式は sensorData[j + 1] ← sensorData[j] となります。
3. 空欄[c]：whileループを抜けた時点で、変数 j は「tempValue より小さい要素のインデックス」または「0（配列の先頭を突き抜けた状態）」を指しています。したがって、tempValue を挿入すべき正しい位置はその一つ後ろの sensorData[j + 1] となります。式は sensorData[j + 1] ← tempValue です。

問6：シェルソート（改良挿入法とギャップ縮小）

ネットワーク機器を通過する大量の通信パケットのシーケンス番号を整列する処理を最適化するため、挿入ソートの弱点（遠く離れた要素の移動コストが高い）を克服したシェルソートを採用しました。このアルゴリズムは、最初に要素間のギャップ（間隔）`h` を設けて大まかに整列させ、段階的にギャップを縮めていく手法です。

以下の初期配列 `sequenceNumbers` を対象に実行したとき、『最初の外側の while ループ（h = 2のときの処理）がすべて完了し、次のギャップ計算（h ← h ÷ 2 の商）が実行される直前』における配列の並び順として正しいものを選びなさい。

  • 初期状態の配列（sequenceNumbers）: {80, 50, 90, 40, 60}
  • ※配列のインデックスは1から始まり、要素数は5です。
○手続: shellSortPackets(整数型の配列: sequenceNumbers) 整数型: i, j, h, tempValue 整数型: n ← sequenceNumbersの要素数 h ← n ÷ 2 の商 while (h ＞ 0) for (i を h + 1 から n まで 1 ずつ増やす) tempValue ← sequenceNumbers[i] j ← i - h while (j ＞ 0 and sequenceNumbers[j] ＞ tempValue) sequenceNumbers[j + h] ← sequenceNumbers[j] j ← j - h endwhile sequenceNumbers[j + h] ← tempValue endfor h ← h ÷ 2 の商 endwhile

設問

h = 2 での処理が完了した直後の配列の状態はどれか。

  • ア： {40, 50, 60, 80, 90}
  • イ： {80, 40, 60, 50, 90}
  • ウ： {50, 80, 40, 90, 60}
  • エ： {60, 50, 80, 40, 90}
  • オ： {60, 40, 80, 50, 90}
  • カ： {40, 50, 80, 90, 60}
  • キ： {80, 40, 90, 50, 60}
  • ク： {60, 80, 40, 90, 50}

正解：オ

【トレース詳細】
初期状態: {80, 50, 90, 40, 60}, n = 5
最初の h の値: 5 ÷ 2 の商 = 2

■forループ (i = 3)
tempValue = 90, j = 1。
arr[1](80) ＞ 90 は偽。whileには入らず arr[3] に 90 をセット。配列変化なし。

■forループ (i = 4)
tempValue = 40, j = 2。
arr[2](50) ＞ 40 は真。arr[4] に 50 を移動。j = 0 となりwhile終了。
arr[2] に 40 をセット。
この時点の配列: {80, 40, 90, 50, 60}

■forループ (i = 5)
tempValue = 60, j = 3。
arr[3](90) ＞ 60 は真。arr[5] に 90 を移動。j = 1 に。
arr[1](80) ＞ 60 は真。arr[3] に 80 を移動。j = -1 となりwhile終了。
arr[1] に 60 をセット。
この時点の配列: {60, 40, 80, 50, 90}

すべての i (3〜5) の処理が完了し、h=2のパスが終了した直後の状態はオとなります。

問7：クイックソート（分割処理とポインタ交差）

オンライン対戦ゲームのランキングシステムにて、プレイヤースコアを高速にパーティション分けする処理を実装しています。両端からポインタを進め、基準値（ピボット）に対して不適切な位置にある要素同士を交換するHoareの分割方式を用いたクイックソートです。

初期配列 `playerScores` に対して `quickSortScores(playerScores, 1, 5)` を呼び出したとき、『1回目の while (true) ループを break で抜け、左右の部分配列に対する再帰呼び出しが行われる直前』の配列の並び順として正しいものを選びなさい。

  • 初期状態の配列（playerScores）: {55, 20, 80, 40, 90}
  • ※配列のインデックスは1から始まり、要素数は5です。
○手続: quickSortScores(整数型の配列: playerScores, 整数型: left, 整数型: right) 整数型: pivotScore, i, j, tempValue if (left ≧ right) return endif pivotScore ← playerScores[(left + right) ÷ 2 の商] i ← left j ← right while (true) while (playerScores[i] ＜ pivotScore) i ← i + 1 endwhile while (playerScores[j] ＞ pivotScore) j ← j - 1 endwhile if (i ≧ j) break /* while(true)を抜ける */ endif tempValue ← playerScores[i] playerScores[i] ← playerScores[j] playerScores[j] ← tempValue i ← i + 1 j ← j - 1 endwhile quickSortScores(playerScores, left, j) quickSortScores(playerScores, j + 1, right)

設問

1回目の再帰呼び出しの直前（break直後）における配列の状態はどれか。

  • ア： {20, 40, 55, 80, 90}
  • イ： {55, 20, 40, 80, 90}
  • ウ： {40, 20, 55, 90, 80}
  • エ： {20, 55, 40, 80, 90}
  • オ： {40, 55, 20, 80, 90}
  • カ： {55, 40, 20, 80, 90}
  • キ： {40, 20, 55, 80, 90}
  • ク： {55, 20, 80, 40, 90}

正解：イ

【トレース詳細】
初期呼び出し: left=1, right=5
pivotScore = playerScores[(1 + 5) ÷ 2 の商] = playerScores[3] = 80
i = 1, j = 5

■while(true) 1周目
iを右へ進めるループ:
arr[1](55) ＜ 80 なので i=2。
arr[2](20) ＜ 80 なので i=3。
arr[3](80) ＜ 80 は偽なので i=3 で停止。

jを左へ進めるループ:
arr[5](90) ＞ 80 なので j=4。
arr[4](40) ＞ 80 は偽なので j=4 で停止。

i(3) ≧ j(4) は偽であるため、交換を実行。
arr[3](80) と arr[4](40) をスワップ。
配列は {55, 20, 40, 80, 90} に変化。
i ← 4, j ← 3 に更新。

■while(true) 2周目
arr[4](80) ＜ 80 は偽なので i=4 で停止。
arr[3](40) ＞ 80 は偽なので j=3 で停止。
i(4) ≧ j(3) が真となり、break が発動。

再帰呼び出しに入る直前の配列の状態は {55, 20, 40, 80, 90} となります。
