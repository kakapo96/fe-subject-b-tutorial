【科目B対策】データ構造：木構造（ツリー）

木構造は、データ同士の「親子関係」を表すデータ構造です。現実の木とは逆で、「一番上が根（ルート）で、下に向かって枝分かれしていく」のが特徴です。

テーマ①：木の基本用語と「2分探索木」

基本情報技術者試験では、枝分かれが「最大2つまで」の2分木（バイナリツリー）が最もよく出題されます。

絶対に覚えるべきツリー用語

  • ノード（節）： データを格納している丸い箱のこと。
  • ルート（根）： 一番上にある大元のノード。
  • リーフ（葉）： 一番下にあって、それ以上子供を持たないノード。
  • ポインタ： 親から子へ向かう「矢印」のこと（普通は「左の子」と「右の子」へのポインタを持つ）。

🔥 超重要：2分探索木のルール

2分木の中でも、データを探しやすくするために以下のルールで並べたものを「2分探索木（バイナリサーチツリー）」と呼びます。試験に出る木は9割がこれです。

  • 「左の子孫はすべて、親より小さい」
  • 「右の子孫はすべて、親より大きい」

※このルールがあるおかげで、「50を探したいな。今の親は70だから、左の道に進もう！」という風に、一瞬でデータを探し出せます（2分探索と同じ原理）。

テーマ②：木の「走査（そうさ）」３パターン

木にぶら下がっているすべてのデータを、順番に見て回ることを「走査」と言います。いつデータを取り出すか（読むか）によって、3つの名前に分かれます。

【１】 先行順（前順 / 行きがけ順 / Pre-order）

  • 「ノードに初めて着いた（左側を通った）瞬間に読む」
  • 順番： 自分（親） → 左の子 → 右の子
  • 用途： フォルダのツリー構造をそのままテキストで書き出す時などに使います。

【２】 中間順（間順 / 通りがけ順 / In-order）

  • 「左の子を見終わって、自分の下側を通った瞬間に読む」
  • 順番： 左の子 → 自分（親） → 右の子
  • ★試験の最頻出ポイント★
    「2分探索木」をこの中間順で読むと、データが必ず小さい順（昇順）に出てきます！

【３】 後行順（後順 / 帰りがけ順 / Post-order）

  • 「左右の子を両方見終わって、自分の右側を通って帰る瞬間に読む」
  • 順番： 左の子 → 右の子 → 自分（親）
  • 用途： 数式の計算（逆ポーランド記法）や、ファイルを一番下（葉）から順番に削除していく時などに使います。

本番形式：木を走査するプログラム

木構造をなぞるプログラムは、必ず「再帰呼び出し（自分自身を呼び出す）」を使って書かれます。たった数行のコードですが、非常に強力です。

  • node は木を構成する1つの節点（データ）を表します。
  • node.left は左の子、node.right は右の子を指します。
// ツリー全体をなぞる再帰関数
関数 traverse(ノード型: node)
    
    // 【終了条件】 子が存在しない（空っぽの）場所にきたら引き返す
    if (node == null)
        return
    endif
    
    // ========================================
    // ※ここに「出力(node.値)」を書くと【先行順】
    // ========================================
    
    // まずは左の道を一番下まで突き進む！
    traverse(node.left)
    
    // ========================================
    // ※ここに「出力(node.値)」を書くと【中間順】
    // ========================================
    
    // 左が全部終わったら、次は右の道を突き進む！
    traverse(node.right)
    
    // ========================================
    // ※ここに「出力(node.値)」を書くと【後行順】
    // ========================================

本番の試験で「穴埋め」にされるポイント

木構造のプログラム問題は、「どのタイミングでデータを出力するか」の1点に尽きます。

狙われるポイント①：出力処理（print）を入れる場所

問題の例
「2分探索木に格納されたデータを、昇順（小さい順）に出力するプログラムになるよう、空欄[ a ]に適切な処理を入れよ。」
正解の形
traverse(node.left)
print(node.val) // ←中間順の場所
traverse(node.right)
なぜ？
2分探索木では「左の子 ＜ 自分 ＜ 右の子」のルールでデータが配置されています。したがって、小さい順に取り出すには「左の処理が終わったあと、右の処理に行く前」のタイミング（中間順）で自分を出力する必要があります。

狙われるポイント②：木からデータを探し出す再帰処理

問題の例
木の中から目的の値 target を見つける関数。node.val < target だった場合、次に探すべきはどこか？
正解
search(node.right, target)
なぜ？
今のノードの値がターゲットより「小さい」ということは、探しているターゲットはもっと「大きい」数です。2分探索木のルールに従い、大きい数が集まっている「右側の道（node.right）」に進まなければならないからです。

【暗記ポイント】
木構造の走査（なぞり方）が出たら、「行き・通り・帰り」の3パターンのどこで読み取るかだけを意識してください。
特に「2分探索木 × 通りがけ（中間順）＝ 小さい順に出力」は、試験でボーナス問題になる最強の公式です！
