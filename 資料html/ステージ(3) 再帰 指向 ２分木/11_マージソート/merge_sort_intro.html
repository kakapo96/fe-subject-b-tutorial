【科目B対策】マージソートの仕組みと擬似言語

マージソートは、クイックソートと同じ「分割統治法（分けてから解決する）」の仲間です。
要素が「1個」になるまでとにかく半分に割り続け、くっつける（マージする）時に小さい順に整えながら合体させるのが最大の特徴です。

テーマ：限界まで割ってから、綺麗にくっつける

バラバラに並んだ5つの数字を昇順（小さい順）に並べ替えます。
最初の配列： [5, 3, 4, 1, 2]

マージソートのたった1つのルール

「要素が1つになるまで半分に『分割』する。その後、隣り合うグループ同士の先頭を見比べて、小さい方から順に取り出して『結合（マージ）』する。」

【前半戦：分割フェーズ】 とにかく半分に割る

  • 1回目の分割： [5, 3] と [4, 1, 2] に分ける。
  • 2回目の分割： さらに半分に割る。
    左側は [5] と [3]。
    右側は [4] と [1, 2] に分ける。
  • 3回目の分割： 右側の残りを [1] と [2] に分ける。
  • これで全員が「1人ぼっち（要素数1）」になりました。ここから後半戦です！

【後半戦：結合フェーズ①】 1人ずつを合体！

  • [5] と [3] を合体させます。小さい順に取り出すので「3」が先、「5」が後。
    結果： [3, 5]
  • [1] と [2] も合体させます。
    結果： [1, 2]
  • （※「4」は今回はお休みで待機します）

【後半戦：結合フェーズ②】 グループ同士を合体！

  • 待機していた [4] と、さっき作った [1, 2] を合体させます。
  • お互いの先頭を見比べます。「4」と「1」なら「1」が小さいので取り出す。次は「4」と「2」で「2」を取り出す。最後に「4」。
  • 結果： [1, 2, 4]

【後半戦：結合フェーズ③】 最後の合体！

  • 残った2つの大きなグループ [3, 5] と [1, 2, 4] を合体させます。
  • 先頭を見比べて、小さい方を取り出していきます。
    1. 「3」と「1」 → 1
    2. 「3」と「2」 → 2
    3. 「3」と「4」 → 3
    4. 「5」と「4」 → 4
    5. 残った 5
  • 結果： [1, 2, 3, 4, 5]
    並び替え完了です！

本番形式：マージソートの擬似言語

クイックソートと同様に再帰呼び出し（自分自身を呼び出す）を使います。最大の特徴は、合体（マージ）させるときに「一時的な作業用配列（ワーク配列）」を必ず使う点です。

  • 配列 data には、バラバラの数字が入っているとします。
  • 配列の要素番号（インデックス）は 1 から始まります。
// 変数の準備
〇整数型の配列: data
〇整数型の配列: work        // マージ用の一時的な作業配列

// マージソートを行う関数（left: 範囲の左端, right: 範囲の右端）
関数 mergeSort(整数型: left, 整数型: right)
    〇整数型: mid, i, j, k
    
    // 【終了条件】 要素が1つ以下なら分割をやめる
    if (left >= right)
        return
    endif
    
    // 真ん中を計算して、左右に分割する
    mid ← (left + right) ÷ 2 の商
    
    // 【再帰呼び出し】 左半分と右半分をそれぞれさらに分割！
    mergeSort(left, mid)        // 左半分
    mergeSort(mid + 1, right)   // 右半分
    
    // ==========================================
    // ここから下は【結合（マージ）フェーズ】
    // ==========================================
    
    i ← left       // 左グループの先頭
    j ← mid + 1    // 右グループの先頭
    k ← left       // 作業用配列の書き込み位置
    
    // 左右両方のグループに要素が残っている間、小さい方を取り出してworkに入れる
    while (i <= mid and j <= right)
        if (data[i] <= data[j])
            work[k] ← data[i]   // 左の勝ち！
            i ← i + 1
        else
            work[k] ← data[j]   // 右の勝ち！
            j ← j + 1
        endif
        k ← k + 1
    endwhile
    
    // 左グループに余った要素があれば、そのままworkのお尻にくっつける
    while (i <= mid)
        work[k] ← data[i]
        i ← i + 1
        k ← k + 1
    endwhile
    
    // 右グループに余った要素があれば、そのままworkのお尻にくっつける
    while (j <= right)
        work[k] ← data[j]
        j ← j + 1
        k ← k + 1
    endwhile
    
    // 綺麗に合体した作業用配列(work)の中身を、元の配列(data)に戻してあげる
    for (k を left から right まで 1 ずつ増やす)
        data[k] ← work[k]
    endfor
    
関数おわり

本番の試験で「穴埋め」にされるポイント

マージソートは「2つの山から、小さい順にカードを引いていく」ようなイメージを持っておくと解きやすいです。

狙われるポイント①：再帰の終了条件

空欄の例
if ([　a　])
    return
正解
left >= right
なぜ？
クイックソートと全く同じです。「要素が1個だけ（左端と右端が同じ場所）」になったら、それ以上は半分に割れないため、そこでストップ（return）します。

狙われるポイント②：再帰呼び出しの引数（分割位置）

空欄の例
mergeSort([　b　], right)
正解
mid + 1
なぜ？
全体を真ん中（mid）で真っ二つに割ります。左半分のグループは left から mid まで。右半分のグループは、その次の mid + 1 から right までになります。

狙われるポイント③：小さい方を取り出す比較

空欄の例
if ([　c　])
    work[k] ← data[i]
正解
data[i] <= data[j]
なぜ？
ここがマージ（結合）の心臓部です。左グループの先頭（data[i]）と、右グループの先頭（data[j]）を比べます。
昇順に並べたいので、左側の方が小さければ（または同じなら）、左側の要素を新しい配列（work）へ書き込みます。

【試験で1秒で見抜くコツ】
関数の前半で「自分自身を2回呼び出して（再帰）」おり、その後、後半で「work などの別の一時的な配列を使って、合体させるようなwhileループが3つ並んでいる」のを見たら、それは間違いなく「マージソート」です！
